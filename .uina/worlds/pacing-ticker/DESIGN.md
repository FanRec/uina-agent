# pacing-ticker World 当前设计

pacing-ticker 提供自主节拍机会、节拍状态查询和一次性提醒。周期机会受主体忙碌检查、人类活动冷却、退避、次数限制和暂停控制；一次性提醒使用相同调度器，但按自己的截止时间触发。

符合条件时发送一个 `pacing-opportunity` 事件：`queued`、`internal`、`channel: "world"`，事件 ID 使用 `pacing-opportunity:` 前缀加 UUID，跨进程重启和扩展重载保持唯一。主体忙碌、刚与人交互、外部活动退避、每日次数达到上限时不会发送。

节拍器的内部计时变化、下一次触发时间和冷却变化不是主体事件，只通过 `status` 查询。停用时取消计时器、监听器和后续事件出口。

提醒通过 `set_reminder` 设置相对秒数和内容，可由 `list_reminders` 查看，或在到期前用 `cancel_reminder` 取消。引用在持久状态中递增为 `r1`、`r2`……。到期时发送独立 `reminder-due` 内部事件，正文再次呈现提醒内容；它只进入主体队列，不自动执行内容或向外发送。提醒不受节拍暂停、退避和日配额影响，主体忙碌时排队；Ticker 停用或进程离线时保留，到期后重新启用会补投。

提醒在事件入队成功且移除状态写盘成功后才从待触发列表删除。入队失败会保留并在 15 秒后重试。若进程在事件入队成功、删除状态落盘前崩溃，重启后可能再次入队；同一提醒的重复事件使用相同 `reminderRef`，因此提醒投递是至少一次语义。
