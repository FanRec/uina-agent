# Live2D World 当前设计

动作创作、运行调用、模型接入与故障排查见 [Live2D 动画与模型适配手册](./README.md)。本文说明内部设计。

当前姿态、动轨迹交接、实时底层退出、持续反射与嘴型规则及最终验证见 [合成设计](./COMPOSITION.md)。本文后半部分按轮次保留历史证据，不代替当前规则。

Live2D 是身体执行端与状态适配层，通过宿主 `expose` 提供具身端点和声学电平接收端。它消费回合事件、动作调用和播放电平，不主动唤醒主体。Core 不承载动画、音频或 VTS 策略。

具身端点 ID 为 `live2d`，定向线索使用 `<cue id='nod' target='live2d'/>`。端点身份与当前模型身份分开，切换模型保持同一端点；旧 `live2d_mo` 不提供兼容别名。

## 动作定义与编译

`motion.ts` 提供 TypeScript 声明式动作 module：多轴关键帧、保持姿态、顺序、并行、延时、重复与时长/强度变换。原始定义不持有身体、租约、时钟或设备；编译器展开并校验内容、推导通道，生成不可变轨道。`sampleMotion` 是离线检查与生产播放共用的采样 interface。动作内容统一在 `motion-library.ts`，逻辑轴和范围在 `motion-axes.ts`；`model-adapter.ts` 将已核验模型事实与语义定义编译为转换程序。这个 seam 让新动作保持创作 locality，无需修改播放器，并允许数值回归直接复用生产轨迹。

2026-10-10 模型适配接线：原固定名字 adapter 和硬编码输入优先级 retargeter 已删除。任意输出 ID 由模型定义映射，完整配置保留内置来源和物理关系；cue/express 使用实际能力准入，可选轴省略保持时序。离线准备工具提供专用输入计划、精确物理输出移除与恢复；真实 MO 尚未应用。使用与当前限制见 [MODEL-ADAPTATION.md](./MODEL-ADAPTATION.md)。

命名动作、head/gaze/face 与 beats 意图均经过编译器。cue 仅接受动作目录或基准姿态的精确名称，旧别名、冒号修饰和逗号复合语法已删除。目录同时生成 cue 能力声明与工具枚举。呼吸、语流、重音和待机轨迹也从目录采样，随机触发、音频权重、眨眼准入与所有权仍由执行机制负责。创作与播放语义见 [动作创作](MOTION-AUTHORING.md)。

## 动作所有权与连续性

`MotionDirector` 拥有动作意图、姿态限时、通道租约与合成；其动力学实例是私有的。`BodyDirector` 只负责参数位置、速度与加速度，不接收姿态、到期回调或回正策略。通道按 head、torso、gaze、eyes、mouth 分组，优先级为待机 < 反射 < cue < 显式动作 < 急停。启动前须获得全部请求通道，冲突时在驱逐旧租约前拒绝；模型缺失的可选轴由适配器在申请前省略。互不相交的动作并行；命名表演默认 atomic，即兴片段默认局部让位，作者可覆盖。外部租约不能跨合成器使用，同一个租约不允许两条竞争时间线；释放租约取消其执行。交接尾段短暂保留视觉贡献，但不保留执行所有权。详细设计见 [COMPOSITION.md](./COMPOSITION.md)。

每个播放实例固定启动基准快照，偏移轨道依此解释；面部从 neutral 重建绝对目标。顺序片段保持分支前值，短并行分支保持终值。接管时最新旧轨迹继续推进，与新轨迹交叉混合；更早的交接合并为当前残余。正常退出融回实时底层合成结果，再释放租约。留存保存完整通道目标，新姿态或新动作渐进替换它。普通取消退出尾段；急停、断连和模型切换清空尾段。

创作片段可自由复合；`atomic: true` 另行表达整场所有权：任一通道被抢占就取消整场。产品命名表演默认原子、即兴片段默认局部让位。外部租约须在申请时选择 atomic。原子取消不回滚已经呈现的效果。

每个基准姿态也从完整 neutral 参数重建，省略字段恢复默认值。反射、呼吸、语流摆动、重音和视线补偿合并进动力学目标。普通眨眼是独立的眼睑开合波形，不通过切换整只眼睛的响应速度实现；新眨眼只在眼睛空闲时启动，已开始的眨眼总会自然完成，避免接管/释放时切断波形。仅占用通道而不播放节拍的动作（如物理翻转）保持接管时的目标，基准姿态到期也不能覆盖它。所有权切换只改目标，保留输出位置、速度与加速度。取消同样通过连续动力学收势。

时钟使用单调时间。节拍年龄、目标轨迹、姿态到期与参数动力学由同一渲染推进驱动；不再用另一组异步定时器切拍，等待画面未推进时动作不会先宣布完成。渲染推进完整经过时间，不截断到 100ms，卡帧时间以不超过 1/60 秒的小步采样轨迹，动力学内部以不超过 1/120 秒推进。限时姿态按到期边界重新合成所有权，剩余时间继续推进。卡住的事件循环仍会丢实际展示帧，小步计算不能补回屏幕帧率。

动力学使用三重实极点解析响应，目标突变时位置、速度、加速度连续；静止目标不欠阻尼弹跳。动作切拍采用端点速度/加速度为零的五次缓入缓出；snappy、smooth、gentle 控制过渡与退出段长度及响应速度。nod 是完整下探/回位轨迹，shake 是完整左右往返，lowered/lifted 与 turn_left/right 才是静态目标。随机待机换姿保留 4..6° 的可见偏头/重心移动，约 1100ms 缓入、停留、1300ms 缓出；说话、反射或主动动作介入时让位。生理微动、语流和重音保留较小幅度，不再每次叠加一个夸张跳变。重复焦点通知不会重置限时姿态。

基准姿态为日常轮廓留出动作余量，头部最大基准偏角 7°；表情保持绝对幅度与不同特征，强度对眼睑从正常开放度插值。shy 使用害羞表情，peek_back 最终看回 user；double_nod 组合两次轻重、时长略有区别的完整点头。不同轴允许并行，同轴重叠只允许明确偏移相加，绝对目标竞争在编译时失败。没有肩部、手部和特效通道时，描述不声称会耸肩、托腮或发光。

口型在合成器内按开放余量混合，随后进入统一动力学；客户端不再用 max 旁路覆盖。`withSpeech` 将 blend/exclusive 策略编译到嘴部轨道，哈欠默认保护编排，下一步与交接退出渐进恢复语音。工具 speech 可显式覆盖；物理独占时语音不能越权。没有覆盖嘟嘴的常驻微笑地板。

## 模型绑定与 VTS

只读当前模型 `.vtube.json` 的保存绑定，并查询 VTS `Live2DParameterListRequest` 获取真实 Cubism 参数范围和默认值。保存映射端点与模型真实范围是不同事实；眼睑意图 1 对应模型正常睁眼默认值，0 对应闭眼端点，再按保存映射反算输入。当前 MO 的真实眼睑范围是 0..1、默认 1，而保存映射上端是 1.9；不能把 1.9 当成正常睁眼值。默认 relaxed 的眼睑意图已改为 1，不再常驻半睁。Windows 默认从运行中的 VTS 可执行文件找到模型目录；也可设置 `UINA_VTS_MODELS_DIR` 指向 `Live2DModels`。找不到配置或参数清单失败时保持离线并报告原因，不注入猜测的参数。

模型适配定义赋予输出参数逻辑语义；控制资格还需真实输入、绑定、范围及来源核验。多轴争用同一输入或输出时拒绝赋予独立能力。明确接受的单轴 fanout 会保留耦合资源；未知输出的耦合保守占用全部通道。准备器可生成专用输入与绑定补丁，解除指定参数的物理写入。每帧包含可用轴的中性目标，避免 VTS 保留旧口型。

具身在线状态直接投影客户端是否可控制，不维护第二份回调缓存。status 区分 API 未连接、API 已连接但控制未就绪、可控制，并显示鉴权、初始化阶段、端点和故障；API 未连接不代表 VTS 软件没启动。连接握手超时重试，传输错误保留原因。连接就绪要求鉴权、参数清单、当前模型保存配置、热键查询和模型切换订阅完成。模型切换订阅在读取模型配置之前建立；切换立即清理旧绑定并重新连接，初始化中的旧读取也不会混入新模型。每次只允许一个未确认参数帧，缓冲未清空时跳过旧帧；确认失败/超时转为离线重连。旧连接异步结果无法恢复新连接状态。停机与断连会停止时钟、取消动作、释放租约并清空音频包络；可以重新启动。

status 展示实际可用轴、校准状态、不可用原因、校准饱和与传输证据。MO 当前配置的共享绑定与物理覆盖证据见 [MO 比较](MO-MODEL-COMPARISON.md)；预设含自定义嘴部语义，仍需真实范围与视觉校准。修改保存配置后，客户端停止旧控制并等待 VTS 明确模型重载事件；重连本身不能证明 VTS 已读入新配置。VTS 侧输入平滑、动画、表情和物理仍影响最终视觉效果。

`model-motion.ts` 独家拥有物理翻转轨迹和归位。读取原位置、角度和大小，每次前进 15°、正常间隔 40ms，使用 VTS 原生 80ms 短过渡，最后等待过渡完成。请求确认慢时延长时间线并保留每个中间角度；不跳步、不使用零时长瞬移。绝对轨迹避免相对增量对未完成移动重复计账。结束或取消后恢复原变换，等待收势并回读核实；换模型后不向新模型应用旧变换，清理/回读失败返回 unknown。表情时间线完成只表示参数请求被接受，不声明视觉已确认。

## 音频与线索

TTS Bridge 在 feed 线程计算 20ms PCM 电平窗口，按采样区间存储。进度快照根据 DAC 时钟选择当前可听样本的窗口；没有可靠 DAC 时钟则使用 submitted_samples，并如实标记时钟质量。未播放的未来缓冲不能提前驱动口型。停流清空窗口，旧流的测量不能写入重启后的新流。过大的单包可以进入空缓冲，不会因大于缓冲水位而永久等待。

`AudioObserver` 在样本间保持输入，按渲染节拍做攻击/释放与增益归一化，超时则平滑闭嘴。重音检测依据电平上升和不应期，持续响声不会固定周期重复点头。声音停止时平滑释放；身体断连/停机时直接清空，避免重连继承旧声音。

启用正文朗读时，TTS 在分句中保留 cue 与清洗后的字素偏移，随段 metadata 发送。Bridge 到实际播放进度对应位置才发 cue，具身扩展负责路由。无正文朗读时直接按文本输出触发。每个输出流的纯尾部 cue 保留自己的播放完成边界；`output_end` 等待尾句投递完成，再通知 `turn_end`，句数只取当前来源，不借用上一轮仍在交付的快照；失败/取消来源的迟到事件丢弃，同一段的重复事件不重复执行。完成来源在后续轮次清理；SSE 丢失完成事件时仍有未收束状态，不能把事件暂存说成完全有界历史。迟到的旧投递响应不得回滚新来源的交付账。

段内 cue 位置沿用播放进度/总时长的字素比例估计，**不是词级强制对齐**；它消除了模型生成到音频缓冲的提前量，但无法保证每个词精确到拍。非 DAC 播放后端、SSE 事件中断或丢失、模型侧物理叠加仍需要真实设备观察。
