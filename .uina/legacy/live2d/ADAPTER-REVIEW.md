# 模型适配与执行反馈审查

日期：2026-10-10。范围：近期 Live2D 模型适配、配置准备、动作准入、播放结果及其测试。运行使用方法以 [README](./README.md) 为准。

## 情况分析

控制链路是：逻辑动作 → 合成与动力学 → adapter 编码 → VTS 输入 → 保存绑定 → 模型参数；物理、表情和模型动画也会写参数。独立控制需要这些路径的资源归属一致。参数 ID 是否标准、请求是否接受、动作时间是否走完，均不能单独证明这条链路成立。

用户截图显示 MO 表情和 focused 姿态因共享输入及物理输出冲突被拒绝，整模型翻转成功但附带表情未执行。源码确认拒绝发生在租约申请之前，并非动作已经播放后“拉不动”。翻转使用独立的整模型移动接口，因此能执行不能证明面部参数可用。截图不是本次实时设备验证。

当前共享输入检查和物理所有权检查应保留。必需轴缺失会改变表达，整体拒绝合理；可选装饰可以明确省略。将所有轨道改为可选、强行注入、统一改参数 ID，均不能解决独立性问题。准备工具已有精确绑定/物理输出补丁及恢复机制；存在该工具不代表实际模型已经准备好。

## 已修正的问题

| 问题 | 修正与可验证结果 |
| --- | --- |
| 动作结果相减全局注入计数，待机和旧动作确认可能混入 | 合成器给最终采样帧标记实际播放贡献；adapter 转换为输入集合；客户端在发包时捕获贡献归属，ACK 只更新该请求的记录 |
| 时间线结束时本场请求还未确认 | 先释放租约，停止记录新请求，再等待已有请求结算；共用原注入超时，断线明确失败；取消仍即时返回 |
| 局部通道被抢占却 partial=false，且说整段未执行 | 分开记录适配 omissions 和运行中 interruptedChannels，任一存在都标记 partial；描述后续片段停止，不抹去已呈现部分 |
| 适配省略只提供轴名，原因丢失 | omissions 保留轴和原因；omittedAxes 从它派生，避免两份可变状态 |
| 模型准入失败一律被称为通道申请失败 | 分开 model_not_ready、motion_not_admitted 和 channel_conflict，不误导为租约争抢 |
| 姿态准入未主动核对文件变化，且结果不报告可选省略 | 在线先核验事实指纹；失效时拒绝更新意图；接受本地意图明确使用 local_intent，并报告省略 |
| 多目标准备给不同校准曲线分配同一个输入 | 每目标生成独立输入，保留共享逻辑轴；准备、应用、再编译及重复计划验证通过 |
| 自动校准可能退化为常量，却授予可控能力 | 自动与作者数值共用同一校准验证，退化时不可用 |
| 测试手动增加全局接受计数，伪装传输完成 | 删除该证据；无协议确认的测试只验证本地生命周期，接受证据由生产客户端配合模拟协议响应验证 |

## 重构取舍

保持动作编译器、合成器、适配程序、VTS 客户端和运行时各自的真实职责。不增加任务框架、总线或第二套播放器；不修改 Core。租约仍是播放归属的来源，传输记录仅保存请求证据，不拥有播放状态。

合成器只暴露当前最终采样帧的贡献，不把卡帧期间的内部积分步当成送达帧，也不追溯动力学残余为完整轨迹。适配程序封装轴到输入的转换，运行时无需知道模型输出 ID。客户端共用一个请求结算入口，避免 ACK、错误和断线重复记账。全局计数保留用于设备诊断，不再充当单动作证据。

多目标准备采用独立输入，因为不同参数校准关系不必相同。若以后要共享输入，必须证明整条曲线一致；当前没有必要为这项优化引入额外推导机制。

## 后续实施顺序

1. **真实 MO 准备与核验。** capture 当前模型 → 预览精确计划 → 核验/创建输入 → 关闭 VTS 后重新生成计划与备份应用 → 重新加载并 capture。只解除程序目标的冲突物理输出，保留其余物理。实际文件尚未在本次改动中应用。
2. **单轴与组合校准。** 检查方向、中性位、舒适范围、输入默认后的回退姿态，以及转头/躯干、嘴形/眼笑的独立性；验收头发衣物物理。再检查命名动作、条件反射、语音、抢占、停止和模型切换。
3. **补可重复的画面质量诊断。** 记录采样、动力学、编码、确认间隔与饱和，配合实际预览。有限帧确认不能证明短动作峰值送达，也不能证明可爱自然。
4. **按真实需要细化来源协作。** 当前热键统一独占全身、模型动画静态冲突拒绝、来源低频观察，仍较保守。待真实资源与行为核实后再细化；不先做无限混合或默认绕过所有权。
5. **用另一款真实模型验证适配。** 模拟模型的任意 ID 和准备测试是程序证据，不能代替跨真实模型画面验收。
