# 动作过渡、灵动性与 VTS 状态修复（2026-10-10）

本轮回应用户继续观察到的偶发抽动、切换不舒适、表情语义偏差，以及 VTS 软件启动却显示离线的问题。用户明确希望保留明显的随机待机动作和灵动可爱感；实现保留随机换姿，修掉突然发力与突然撤回的过程。最终自然度需要画面评价，不能由自动测试宣布。

## 根因与实施

| 旧行为/机制 | 问题 | 本轮实现 |
| --- | --- | --- |
| 二阶欠阻尼弹簧只保留位置和速度 | 目标和响应速度切换时加速度突变；归一化表情响应较快，角度还会回弹 | `BodyDirector` 使用三重实极点解析响应，保留位置、速度、加速度；从静止到固定目标单调收敛。角度速度上限、硬边界仍是保护性截断，不把边界处称为数学上的完全连续 |
| 每拍直接换目标，异步计时器与渲染分开 | 头部在短拍内跨很大角度，卡住时计时器可以先切拍/完成，画面未展示动作 | 节拍年龄与渲染使用同一推进；大 dt 小步采样每拍。新动作与每次切拍有五次缓入缓出，末尾有 200/320/420ms 退出段再释放租约 |
| 通道接管后保持旧目标，解锁恢复装饰 | 位置没跳不等于发力舒适 | 接管保留动力学状态，新动作从当前目标缓入；重音/语流让位，不用它们突然抢改 cue。退出返回当前基准意图 |
| 待机随机直接加/撤 4..7° | 可见活力来自目标阶跃，偶发偏移像抽动 | **保留 4..6° 可见随机偏头/重心变化**，1100ms 缓入、停留、1300ms 缓出；说话开始时用 650ms 释放权重，主动动作接管时让位。没有永久删掉随机待机 |
| 生理漂移、语流与重音同时大幅叠加 | 无意动作与表演混杂；多正弦和额外脊柱耦合使运动难以理解 | 保留小幅呼吸、微动、语流与重音，删除重复脊柱补偿；随机换姿承担明确可见的待机变化 |
| 眼睛空闲时每帧强制提高响应速度 | 动作释放后整个眼睑目标突然加快；被禁止的眨眼仍暗中走到中途 | 普通眨眼是余弦开合波形，独立于表情动力学；空闲才启动，已开始的波形完成，不因接管硬切。被禁止启动的眨眼不会在解锁时恢复半个波形 |
| 基准姿态大倾角，再加大幅头部动作 | 原姿态与动作碰到 ±30° 等硬上限，细节被截平 | 基准头角保留各自轮廓并留余量（最大 7°）；头动作标定为偏转 12°、下探 9°、仰低 7°；待机随机仍明显 |
| 表情叠加基准的脸红/眼笑/眉毛 | 同一表情在不同底座失真，饱和后多个表情长得一样 | 指定 face 时从完整 neutral 面部编译绝对表情目标；省略字段清零，强度对眼睑从正常开放度插值 |
| nod/shake 是低头/向右的固定值 | 点头/摇头只做半个动作；旧双点头用低头/仰头极值反复追赶 | nod 为完整下探/回位；shake 为左右往返/回位，曲线端点平稳。lowered/lifted 与 turn_left/right 保持静态目标语义 |
| shy 使用 tender_smile；peek_back 仍 side_peek | 实际表演与名字不一致 | 害羞使用 shy 面部并低头避开视线；偷看回用户的最后 gaze 是 user；笑、哈欠、眨单眼与坏笑重新调节幅度和时长 |
| 复合 cue 只取规范 cue 第一拍 | `double_nod,smile` 被压成一次点头 | 保留完整多拍序列，叠加明确属性；两个不同多拍编排缺少时间关系时返回不可解析 |
| “耸肩、托腮、歪嘴、发光”当成实际能力 | 没有肩/手/特效通道，描述让主体误判能力 | 描述改为实际偏头、微笑、抬眉等；明示没有相关通道，姿态说明复用中心清单，删除工具对两拍的无必要限制 |
| `Live2DStateTracker` 缓存连接回调结果 | 创建时客户端已就绪却未收到下一次回调，状态会失真 | 状态直接读取 `VTSClient` 的真实就绪与故障，不再维护第二份在线状态 |
| status 只显示“离线(VTS)” | API 未连、未授权、配置读取失败被混成一个词，无法判断软件是否启动 | 分别显示 API 未连接、API 已连接但控制未就绪、可控制；附端点、鉴权、初始化阶段与错误。API 未连接明确不代表软件未启动 |
| 连接 error 不保存原因，握手可能一直挂住 | 无故障可查，连接可能不重试 | 保存传输错误，5 秒握手超时清理并重连；代际保护与严格模型就绪保留 |

表情编排、所有权、时间线仍归 `MotionDirector`；参数运动归 `BodyDirector`；眨眼与连续微动归 `PhysiologicalNoise`；VTS 通信状态归客户端。没有新增 Core 接口、独立任务系统或兼容旧错误路径。没有改 MO 保存配置。

- 全量 `pnpm test -- --reporter=dot`：142 个文件通过，1809 项通过，1 项预期失败（1810 项）。随后故障原因保留的小修正经最终聚焦验证：4 个文件、117 项全部通过；类型与构建编译再次通过。
- 新增 `tests/live2d-presentation.test.ts`：目标切换保留加速度、固定表情无回弹、定时器不能抢跑、粗渲染推进不跳拍、节拍边界和退出、两次可见点头、完整左右摇头、全部姿态与表情组合、cue 语义和多拍复合、眨眼准入连续性。
- 状态回归：已连接后才创建 Companion、初始化中 API 已连但不可控制、失败/卡住握手暴露原因并重试、旧模型/连接异步结果不能恢复新状态。
- `pnpm exec tsc --noEmit`、6 条边界检查、`tsc -p tsconfig.build.json` 与 `git diff --check` 通过。完整 `pnpm typecheck`/`pnpm build` 仍有前轮记录的生成目录 Biome 嵌套配置及用户进程占用 native 文件问题，本轮不为此清理目录或停止进程。
- 本机只读 VTSClient 探针成功：ready=true、MO、27 条映射、1 个热键，没有注入参数。**用户截图中旧实例的离线原因未现场复现**，不推断为软件未启动或声称已定位其唯一原因。
- 18 个规范 cue 的数值采样（relaxed 起始、10ms 步进）最大头部速度约 35.29°/s；单点头俯仰范围约 4.99°，摇头 yaw 范围约 7.75°，wink 的 roll 范围约 11.29°。这保留可见动作幅度，并非“全部动作都缩到几乎不动”。
- 本机 6000 个 60Hz 合成步的平均耗时约 0.014ms（单次脚本测量，不是持续负载或尾延迟保证）。时间线调整没有把等待 API 或额外定时器放进每帧路径。

MO 当前的 MouthSmile 保存绑定为 0..1，无法表示负嘴形；眼笑与嘴形共用输入、双眉共用输入、躯干与头部联动。这些真实限制仍会影响表情区分，特别是嘟嘴、单眉和独立身体动作。代码不能凭参数表制造模型没绑定的独立能力。VTS 平滑、物理、其他动画与运行中的旧控制实例仍可能影响最终画面。

屏幕自然度、真实帧率、词级声画同步与截图旧实例的故障来源未验收。需重新加载 Live2D World（本工作树还含前轮核心接缝更新时，应重启 Uina）应用当前模块。卡住的事件循环实际丢帧无法靠离线小步积分补回。
