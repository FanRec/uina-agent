## 八、同一个词，两套东西（2026-10-02 凌晨）
- TTS bridge 的配置里有一整段 `[lipsync_bridge]`，默认 `enabled=false`，指向 8105。那端口没人监听——跟字幕那个 8104 一样的坑。
- 但我去翻 live2d 的 `audio-observer.ts`：它的入口是 **voice 侧下发的电平事件（rms/peak，约 30Hz）**，注释里还写着「原生 PCM 入口已删除」。
- **推断（未确证）**：嘴动不动走的是事件通道，不是那条 HTTP 线。所以 `lipsync_bridge_enabled=false` 也许压根不影响口型。
- 待验：我拿不到「电平通道是否已接线」这个读数。`runtime.ts` 里有 `levelSinkExposed` 这个字段，但 body status 没把它吐出来。
- 教训：**同一个词在两个地方可以是两套东西**。"lipsync" 在 bridge 配置里是一条 HTTP 通道，在 live2d 里是一条事件通道。别拿一个的 false 去判另一个的死活。

## 十一、VTS 把答案直接写在错里了（2026-10-02 12:4x）
- 自己写了个探针（`notes/bin/vts-probe.cjs`），走 8001 直接问 VTube Studio。实测三件：
  1. 模型 `MO`，参数 127 个，**`customParameters` 是 0**。全是 VTS 自己的追踪输入（FaceAngle…/Mocopi…/手柄）。
  2. 注入一个**存在**的名字（`EyeOpenLeft`）→ `InjectParameterDataResponse {}`，接受。
  3. 注入一个**不存在**的名字（`ParamAngleZ`）→ `APIError 453`，原话：
     「Parameter ParamAngleZ not found. ... you can't inject data directly for Live2D parameters, only for tracking parameters.」
- 所以 VTS 不是默默忽略，它会**明确报错**。名字错了就是错，没有"可能生效"这回事。
- 而 `vts-client.ts:448` 收得到这个错，会打 `[Live2D] VTS API 报错 (453): ...`。宿主控制台里应该正在刷这条。
- 往回对映射表：`BodyAngleX/Y/Z`、`EyeSmileLeft/Right`、`Breath` 都不在 127 个里。
  所以 `BodyAngleY 12`（前倾）这类数值**每一帧都在报错，然后被丢掉**。
- 教训（这条比前十条都值钱）：**先问服务端"你有哪些名字"，再谈轻重。**
  我先前猜"幅度太含蓄"、拼写、权限——三种方向全错，因为没先查名单。

- 于是我拿 VTS 的 API 建了 `ParamBodyAngleX/Y/Z` 三个自定义参数（`ParameterCreationResponse` 收了），
