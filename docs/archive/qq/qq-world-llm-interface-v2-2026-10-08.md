## 1. 信息放置原则

根据是否稳定、是否影响当前判断、是否难以发现，决定信息放在哪里，而不是把全部事实都挤进每条消息。

| 内容 | 放置与更新方式 |
| --- | --- |
| 身份/人格 | 用户指定的原始身份段冻结，原样保留；不因精简而替换、迁移或弱化其表达 |
| 外部来源、合成事件、结果真实性 | 通用系统提示声明一次，所有 World 共用 |
| 默认展示时区 | 通用系统提示声明一次；同一会话期间固定 |
| QQ 使用方式、短引用规则 | qq 工具描述一次 |
| 当前绑定账号 | 工具实例描述/参数约束明确；每个独立自动现场标一次账号 |
| 用途、重要场景线索 | 对应 action、scope 或特殊参数的简短描述 |
| 自身完整资料、完整授权、表情目录、成员清单 | 按需查询，结果仍适用且在上下文中时复用 |
| 当前新消息、关系、事件、结果、重要变化 | 当次正文 |
| 传输地址、长游标内部字段、revision、SDK/IO 细节 | 程序与诊断；仅当它们影响我的下一步时，正文给简短结论 |

“写一次”是指不在每个历史事件里重复，不表示 system/tools 只在第一次请求发送。“查一次”是复用仍适用且可见的证据，不表示成员、权限、在线状态永远不变；压缩后证据丢失、重启或失败时，可以按需要重新取得。

## 2. 时区：要知道一次，不需要每屏重复

默认展示时区固定为当前会话的真实时间基准，例如 `Asia/Shanghai`。普通现场不再反复带 `GMT+08:00`。

规则：

- 独立场景给一个完整日期和观察时刻；行内为消息发生时刻。
- 同日可省日期，同一连续块可省重复的分钟；跨日/跨年必须补实际日期。
- 离线保存事实标来源和实际保存/发生时间，不能把新的查询时间当作新的平台观察。
- 原始外部正文里的时间保持原文，不因展示转换而改写聊天内容。
- 特殊来源未转换到默认时区时显式标时区；同一历史会话不应悄悄切换时间基准。若必须切换，要给明确变更标记，旧记录保持可解释。
- canonical 时间继续存 UTC。工具参数仍遵循声明的时间类型；当前带时区 ISO 输入不能因为显示省略时区就变成无时区输入。

例如显示预约为 `2026-10-09 21:00`，实际调用 `reviewAt="2026-10-09T21:00:00+08:00"`。这个偏移在机器参数中承担明确的时间含义，不是需要到处重复的阅读注记。

## 3. 短引用：模型协议，而非临时页面别名

建议使用容易学习的类型前缀：

| 模型引用 | 含义 |
| --- | --- |
| `g30003` | 群会话 |
| `p20002` | 与该用户的私聊会话 |
| `t20002-g30003` | 保留源群的临时会话 |
| `u20002` | 用户身份，不能直接当作会话 |
| `m42` | 消息 |
| `a7` | 附件 |
| `r3` | 已收到的申请/邀请 |
| `f12` | 我保存的待跟进事项 |
| `o5` | 外部操作记录 |
| `e7` | 需要引用或作为证据的事件 |

账号不再出现在每一个 user/message/media ref 中。独立自动现场的页首给一次账号；工具调用的 params.account 给一次账号，所有引用归属于这个账号。普通工具回执已与调用配对，无需每行再次写账号。

示例模型调用（新合同，当前源码尚不接受）：

```json
{
  "action": "speak",
  "params": {
    "account": "10001",
    "target": "g30003",
    "replyTo": "m42",
    "content": [{ "type": "text", "text": "好呀" }]
  }
}
```

`target` 取代这个动作中的 `conversationRef`：它是可发送的会话；相关 message/user 字段保持有意义的命名，不把全部参数压成单字母。群内 poke 仍需要会话目标和用户身份两个字段，不能从“当前焦点”隐式推导路由。

程序约束：

1. 调用账号必须与当前绑定匹配；旧账号历史里的引用不能悄悄解释为新账号对象。
2. 短引用是跨回合稳定对象 ID，不是“本页第42条”。消息、申请、附件、事项、操作等私有对象 ID 在同一 QQ 数据根内不因翻页、重启或换账号重新分配给别的对象；已有事实保存其所属账号，解析时继续检查归属。保存的证据和预约仍可使用它；过期/不可寻址明确失败。
3. 数值只是 fixture。已有稳定内部 ID 可直接缩短编码；平台 opaque flag 或进程内短 ID 不能冒充持久 ID。必要的地址对应保存在 QQ 自己已有的事实日志中，不新增通用的页面 handle registry。
4. 内部 canonical ref、账号隔离、真实地址核验、意图日志和发送顺序保持程序权威；昵称不能作为地址。
5. 新模型协议须同步改 schema、参数解析、模型呈现及恢复/replay 验证。不能只把正文变成 m42，却继续让工具只接受完整 qq-message 引用；也不能用字符长度实验声称此合同已经验证。

## 4. 消息样式

### 普通场景

```text
QQ 10001 · g30003 · 2026-10-08 14:00
人物：小明=u20002，阿岚=u20003

13:58 小明
  m42 今晚来不来？[微笑/14]
13:59 阿岚
  m43 回复m42：我也来
14:00 小明
  m44 那就八点！
  m45 我来开房
```

只有取得真实群名时才附名字，例如 `周末游戏群(g30003)`。不再同时写“QQ群”“会话”“qq-conversation”“group”；g 已经表达类型。头像、表情名称、昵称都不得臆造。

用户已认可：每个独立现场的人物表只给一次名字与真实 u 引用的对应，交错发言不再重复QQ号。连续发言可以共用人名/时间头，每条消息仍保持边界和 m 引用；分隔的发言块重新写名字即可。私聊把对方身份放在会话头，正文区分“我”与对方；单条消息无需强加人物表。

同名时用“小明A/小明B”等阅读标签，在人物表明确对应各自的真实 u 引用；操作参数仍复制 u 引用，标签不是新的可执行地址。人物表随独立现场提供，避免上下文压缩后丢失对应；不增加跨回合标签registry。自身消息写“我”，不反复带自己的 userRef。

提醒正文默认是新交付内容；必要旧消息单独放“前文”。查询结果是读取窗口，不伪装成新消息。正常完整交付不写 coverage/hasMore=false 的例行尾巴；有缺口才给具体省略/截断及真实继续入口。页的结束不表示世界里再无历史。

默认不写 raw trigger，因为可见的@、回复和事件本身已经解释它。若裁剪后的现场不能解释为何提醒，保留真实触发事实与引用；不能把“删掉trigger”当作允许丢失触发消息。元字段安全引用，外部正文缩进并只转义一次，不能让昵称或多行消息伪造新的事实行。

### 申请与互动

```text
QQ 10001 · 好友申请 · 2026-10-08 14:00
r3 小玖(u20009)：一起打游戏
```

申请类型在头部；这类提醒默认待处理，不每行写 pending/state。群邀请另给实际群目标。显示名未取得时只给用户引用。

```text
QQ 10001 · g30003 · 2026-10-08 14:00
13:59 e7 小明(u20002)戳了我
14:00 e8 阿岚(u20003)撤回了m43
```

谁、对象、动作和撤回关系保留。事件 ID 只在可引用/需要证据的场景展示；无模型用途的内部通知 ID 不进入正文。

### 附件

消息中只写 `[图片 a7]`、`[语音 a8]` 或有用的真实文件名。占位是有附件的事实，不表示已看过/听过。图片已附给模型时，标附件与消息的对应，例如 `图1=a7@m42`；下载失败只报告该附件的具体失败。

媒体 URL、缓存 hash、staging 路径不出现。卡片有意义的标题/摘要/实际链接保留；它们是内容，不与传输 URL 一起删除。完整原文、长转发及更多附件必须有可用读取入口。

### 正常与异常回执

```text
已发送 m99
```

目标在对应调用中已明确；查询单条过去操作时则要带目标。这里只省常规正文，外部意图与回执仍完整记账。

```text
发送未确认 o5；可能已发送。
```

system 与 operations 描述已经解释 unknown 的使用方式，不必在每条回执抄完整下一步调用。效果未知的提醒必须可见；不要仅留下 Provider 未运输的结构化 status。

```text
内容1–2已发送 m99
内容3结果未知 o5
内容4–5未发送
```

部分结果按请求 content 的位置定位，不能用模型尚不知道的后台“第N批”代替。保存失败、平台确认但日志故障、拒绝、取消、未派发等状态用简短准确结论区分。

attention 成功给实际生效变化，如 `g30003 仅直接互动提醒`，确有暂停时加到期时间；不用 revision/persisted/effect 三次表达保存。follow_up 返回 f 引用、实际预约与重要变更；关闭不意味着外部目标已完成。

当前绑定账号由实例事实给一次，不放入每条身份引用。完整授权、自身资料和完整能力诊断按需查询。语义前缀只列模型会使用的类型；事件 e 的含义放需要事件证据的字段描述。

### action 描述

| action | 建议描述 |
| --- | --- |
| observe | 读取缺少的现场、目标或附件；按scope选择要看的内容。 |
| speak | 向target发送文字或已有附件；replyTo可引用回复指定消息。 |
| gesture | 简短互动：react回应指定消息，poke戳指定会话中的用户。 |
| attention | 某会话太吵或暂不想被提醒时，可调整后续提醒；不限制主动查看。 |
| follow_up | 想稍后回到某个话题或事项时保存；reviewAt到期只提醒，不自动执行。 |
| account | 处理申请、撤回自己的消息、管理未读标记或修改资料等；结果不代表对方已读。 |

### 只给不容易发现的能力加场景线索

| 位置 | 保留的线索 |
| --- | --- |
| conversation/messages | 接不上话题或需核对具体原文时，读取前文或指定消息。 |
| includeMedia/includeEvents | 图片影响理解时可展开图片；想了解戳、撤回、成员变化等时可带事件。 |
| members | 想@具体群成员或区分同名时查；用户身份不能由好友列表代替群成员关系。 |
| expressions | 想用QQ表情/消息回应但不确定编码时查；不要从词语或Unicode猜平台编号。 |
| operations | 动作效果未知或需核对过去操作时查询；查询不会再次执行。 |
| mark_read | 要管理平台未读标记时使用；普通读取不会自动标已读。 |

这些用“想……时可……”表达用途，不写成“遇到……必须执行某套流程”。不要求聊天前做status，不要求回应前查表情，不要求保存每个承诺；已有明确现场时直接运用。

字段描述只写本字段的区别：target的类型、replyTo的消息归属、resource的来源、reviewAt的带时区ISO与null清除等。删除“单写方”“运行态继续校验”“staging”等实施说明及空描述。复制引用、未知结果、外部来源等通用规则各有唯一位置，不再每个字段重复。

## 7. 对其他输出应用同样原则

| 当前内容 | 新的呈现方式 |
| --- | --- |
| 全量grants和三维长布尔键 | status/capabilities按需返回简短表头；依然区分实现、授权、平台条件 |
| 每条source/覆盖未知注记 | 普通平台查询不例行附长告诫；本地、陈旧、读取失败、截断只在实际发生时显著标出 |
| known false/null/空字段 | 默认值不展开；对当前判断有用的“无”或“未知”明确表达，不能拿省略混淆二者 |
| hasMore=false与完整覆盖说明 | 常规结束无需尾巴；有更多给继续入口，有不可读缺口给准确原因 |
| 重复目标与输入参数 | 正常配对回执省略；归一化、继承、部分执行、错误或单独历史核验时保留实际差异 |
| 完整表情/成员/群目录 | 搜索/分页按需取得，已有有效结果复用；不是隐藏功能或总量硬限制 |
| 多页反复扩大limit | 取增量页，避免把已看内容重新灌入上下文 |
| base64游标全payload | 程序保留绑定/版本/源/恢复语义，使用更短编码；模型只复制，不学习内部结构 |
| AJV全分支错误 | 给所选动作的相关错误，完整报告留details |
| 外部通知反复解释external_event_frame | system已经解释，通知可缩为短类别标记；保留现有来源与三帧配对语义 |
| 外部帧同时放UTC和本地长时间串 | 阅读字段用统一时间基准，原始UTC留canonical事实；需另审查公用帧合同，不能只改QQ正文就声称解决 |
| catalog list重复完整QQ描述 | 一句能力摘要；完整使用合同只在工具定义 |

默认完整查询只代表取得的范围，不表示拥有世界全貌；这个阅读原则写一次。重要未知、拒绝或失败依然在发生处说明。正常路径不给每条消息附防御说明，异常路径也不能为了省token而伪装成功。

## 8. 实施前的反例检查

- 同名：名字相同但u不同；昵称变动不使身份漂移。
- 多会话：相同数字在g/p/u之间不混用；临时会话不升级成好友私聊。
- 多账号历史：所有动作明确账号，旧账号对象不得作用于新绑定。
- 重启：m/r/f/a/o不是页面顺序；bridge重新映射或资源失效时能核验/失败。
- 时间：跨午夜、跨年、离线与延迟提醒不把旧事实变成现在；ISO调用不丢时区。
- 关系：引用较旧消息、撤回、reaction、不同消息的图片仍可对应。
- 安静：普通群消息可以不回应，不被描述训练成每次查询/互动的流程。
- 未知：能力尚未核实与动作可能已执行严格区分，前者可以合法尝试，后者先核验。
- 压缩：关键使用规约留在system/tools，查询证据丢失后能再取得；不依赖页面别名存活。
- 重复：一次性的规约不随批次进入历史；常驻schema仍保持单一真源与可验证约束。

先解决上一轮发现的真实认知缺口，再实施这一完整模型接口。此版本不是只换文案的等价重构；必须同步验证参数调用、账号边界、历史恢复、真实结果及模型运用质量。字符减少只能证明字符减少，不能代替tokenizer/Provider用量或实际QQ互动验收。
