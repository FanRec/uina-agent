# Live2D 动作定义与编译

状态：已实施；当前源码与创作说明见 `.uina/worlds/live2d/MOTION-AUTHORING.md`。

日期：2026-10-10。

## 已确定的要求

用户选择先建设动作定义与编译。个人项目以结果质量为先，允许删除和重写现有动作，不保留旧动作的兼容负担。

创作入口已确定为 TypeScript 声明式定义，支持曲线复用与动作组合。

主体使用命名动作与头部、视线、表情的即兴组合；两者经过同一个编译入口，主体不直接编排底层参数曲线。

本方案留在 Live2D World，复用现有具身端点、回合事实和播放电平接入。主体 Core 不承载动作编译、音频或 VTS 策略。

## 本轮消除的耦合

当前参数播放路径已集中：Runtime 申请租约，MotionDirector 合成并推进，私有 BodyDirector 执行动力学，Companion 重定向并输出至 VTS。

此前动作内容分散：映射表提供幅度与节拍，MotionDirector 识别 nod/shake 并生成轨迹、内联待机与语流曲线，Runtime 内联翻转庆祝。现在内容进入动作目录，播放器按编译轨道执行。

目标是一个有 depth 的动作 module：interface 表达定义、编译与采样，implementation 吸收轨迹展开、组合冲突、通道推导和目标语义。这个 seam 让动作库改变时不修改播放器，提供 locality 与 leverage；设备 adapter 保留真实确认语义。

只抽出 sampleBeat 或重命名文件会得到 shallow module，不满足这个目标。

## 逻辑轴

动作内容使用 head.yaw/pitch/roll、torso.yaw/pitch/roll、gaze.x/y、eyes.left.open 等逻辑轴，不写 Cubism 或 VTS 参数名。

轴目录集中单位、中性值、范围、角度标记与通道归属。头部与躯干使用度；视线和面部使用明确的比例语义。眼睑 0 为闭眼、1 为正常睁眼，眉毛与嘴形保留负值含义。

这个目录同时被编译器与动力学使用。仅在输出 adapter 换名字不算解耦：BodyDirector 的角度判断、范围限制、生理轨迹与中性状态也要改用轴目录。

沿用 head、torso、gaze、eyes、mouth 五个通道。此轮不把仲裁改成每轴独立锁。

## 创作形式

以下示例使用已经接线的创作类型；完整示例见动作创作说明。

```ts
const nod = motion(760,
  track("head.pitch", [[0, 0], [300, -8], [760, 0]], "baseline-offset", "smooth"),
);

const greeting = sequence(
  parallel(nod, smile),
  curiousTilt,
);
```

动作目录集中原子姿态、表情、可复用轨迹、命名编排和描述。定义与组合不持有 MotionDirector、Host、AbortSignal、随机数或设备连接。

### 同义变体与随机接续

同一表演可携带 `variants`（附加原始定义数组）：主定义与变体构成轮换池，cue/express 每次播放均匀随机排除上次选中——连播不重样，服务表演规范"重复时采用有界的轻重、时长、方向变化，不随机改变关键姿势"。约束：

- 变体是作者手写的完整定义（略有差异的纹理），机制不做相似度校验、不提供镜像/缩放变换；池总数 ≥ 2，绑定期逐个编译，非法定义即抛。
- 变体不入全局命名空间、不可独立寻址，agent 仍 cue 单一动作名；`variants` 与主定义共享 description/aliases/playback/atomic/spatial。
- 轮换状态按目录条目对象身份存放：目录快照换代即归零；interrupt 打断不重置（上次选中仍被排除）。
- 语义变体不走此机制：某变体需要被 agent 语义选择时，晋升为独立命名条目。
- status/unknown_motion 提示以 `名字[N变体]` 暴露池总数，不暴露变体细节。

有限动作支持关键帧、明确插值、顺序、并行、延时、重复与时长/强度变换。先满足真实动作，不增加脚本解释器、编辑器协议或动态插件注册。

不同轴的并行轨道可以合并。同轴竞争的绝对目标编译失败；明确声明的增量轨道可以相加。缺少混合语义时不采用“最后一条悄悄覆盖”。

瞬态表演、持续姿态和程序性生理运动可共用轴与轨迹表达，但保留各自的生命周期。普通眨眼的启动门控与完成规则、音频包络的实时输入不强行伪装成固定时长的表演。

## 编译职责

编译器在没有当前姿态、设备连接和渲染时钟时工作，完成以下内容：

1. 展开组合，推导完整时长、轨道与最小通道集合。
2. 校验轴名、有限数值、关键帧顺序、时长、边界和并行冲突。错误指出具体动作、轨道或关键帧。
3. 明确绝对目标与基准增量；强度围绕轴中性值插值，不能把眼睑开放度直接乘强度。
4. 产出独立于源对象后续修改的不可变执行描述。
5. 为播放与离线检查提供相同的采样行为，不存在另一套“仅测试用”的轨迹公式。

非法动作在申请租约之前失败。未知动作不静默降级，NaN、Infinity、空动作不获得通道。

编译成功不等于动作已经执行。

## 播放职责

播放器只认识轨道、逻辑轴、时间、目标语义和所有权，不识别 nod、shake、greeting 等动作名称。

播放启动时绑定完整基准快照与接管起点；编译动作不缓存运行时的当前姿态。退出段回到届时最新的基准，动作内容中的基准增量仍依启动快照解释。

渲染推进是参数动作的时间权威。粗帧推进采样完整经过时间，不用逐拍 setTimeout；离线墙钟不能让画面未推进的动作先完成。

接管、目标切换、取消和退出保留动力学状态。正常收势完成后释放租约；抢占和取消如实返回 cancelled。留存目标在回合结束后仍存在，但可以被新动作或新基准替换。

`atomic: true` 表示全通道一起申请、任一抢占取消整场；默认按通道让位。创作单元与原子播放分开表达；已呈现的效果不回滚。

随机待机、语流与重音的表现参数移入动作内容；运行机制负责触发、输入信号、权重和让位。普通眨眼算法保留独立开合波形，已经开始的眨眼不会因接管中断。

## 与设备的接缝

逻辑轴到 Cubism 参数的转换属于输出 adapter。VTS 保存映射、真实参数范围、共用输入与物理覆盖继续决定实际可呈现能力。

不假设换模型后所有动作都可独立表现，不靠加大幅度掩盖未绑定的轴，不修改真实模型绑定。

整模型翻转仍走 VTS 原生移动、请求确认、插值和归位回读；它与参数播放共用必要的通道所有权。此次将庆祝内容移入动作目录，不提前引入跨设备的复合表演调度平台。

## 旧内容的处理

删除播放器中的动作名称分支，删除散落在 Runtime 的庆祝节拍与执行器中的创作数值。

动作目录可以重新选择动作名、表情、幅度与时长。对外声明、主体提示、工具 schema 与实际编译入口同源生成。

旧 cue 别名、冒号修饰与逗号复合语法不作为兼容要求。保留的输入表达必须有当前使用价值；不存在先解析旧格式再转新格式的第二套执行链。

## 实施顺序与验收

先建立轴目录与纯编译/采样路径，再接入现有播放器与参数动力学；随后重写动作库、意图接入和提示声明，删除旧实现与过时测试。

第一批动作覆盖一次完整点头、左右摇头、微笑、好奇歪头、视线转移、基准姿态与庆祝组合。重点验收以下行为：

- 增加一种新轨迹或组合只修改动作目录，播放器和 Runtime 不需要识别新名称。
- 合法动作的细帧/粗帧采样一致；非法组合在申请通道前失败。
- 内容与源对象修改不能污染已经编译或播放的动作。
- 独立通道并行、部分抢占、外部租约、取消、退出与 latch 保持真实语义。
- 全量姿态与面部状态不残留，姿态限时、焦点停靠、反射和眨眼不会越权。
- 逻辑轴到真实保存映射的转换、设备断连、背压、模型切换和归位失败仍有回归。

编译测试覆盖真实非法输入与组合冲突；播放测试通过生产采样路径观察轨迹，替换内部 prototype spy。保留动力学与眨眼算法的独立数学测试。

完成实现后运行聚焦测试、类型/边界检查与全量测试；完整 typecheck/build 若受已有生成目录或 native 文件锁影响，报告实际阻碍，不清理用户目录或停止用户进程。
