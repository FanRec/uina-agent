### B2-01 [S] rg-installer 的 inflight memo 构成 Promise 自环：无 rg 且无缓存的机器上第一次 grep_file 永久挂起，且下载路径与 node 降级分支双双不可达
- 类别: B（兼 D：把注定失败的降级设计成无限挂起）
- 位置: src/extensions/workspace-tools/rg-installer.ts:61-80（ensureRg）、:82-87（ensureRgInner）、:89-95（downloadRg）；挂起点 src/extensions/workspace-tools/search-core.ts:417（`await ensureRg()`）
- 事实: `ensureRg` 先写 `inflight = ensureRgInner().then(...)` 再 await。`ensureRgInner` 是 async 函数，首个 await（:84 `commandExists`）恢复时外层赋值早已完成；其终点 `return downloadRg()` 里 `inflight ??= downloadRgInner()...`（:90）看到 inflight 已被占位，跳过赋值直接返回外层 promise——`ensureRgInner` 解析为"它自己正在 await 的 promise"，形成自引用环，永不 settle。缓存探测失败 + PATH 无 rg 时：既不下载（`downloadRgInner` 的 `??=` 右侧根本不求值），也不降级 node 引擎（`runGrep` 卡在 await），`lastFailureAt` 负缓存分支（:64/:73）同样不可达（环永不 reject）。
- 证据: 结构同构复现（同三函数三变量语义逐行镜像）输出 `TIMEOUT-forever-pending`；本机因 PATH 有 rg（/e/Work/ripgrep/rg）与 `~/.uina/bin/rg.exe` 缓存短路而不可见；GitHub ubuntu-latest runner 预装 ripgrep，CI `pnpm test`（tests/search-tools.test.ts:261 调 `ensureRg`，`.then` 有值才继续）同样不可见——即该分支从未在任一受支持环境真实执行成功过。旁证：`~/.uina/bin/` 残留 8 个 `extract_tmp_*` 目录（Windows rmSync EBUSY 时 :157-158 finally 清不掉），下载路径确有历史失效场景。
- 移除后果: 删掉 `ensureRgInner` 对 `downloadRg` 的调用改走独立 memo（或整体去掉 `ensureRg` 层的 inflight 复用），node 降级按设计可达；保留现状则 rg-less 机器第一次 grep_file/find_file 依赖 rg 的部分永久无响应。
- 处置建议: 改明确失败/修接——`downloadRg` 用独立于 `ensureRg` memo 的下载 promise；或按 stop-that-shit 直接砍掉下载层（PATH+缓存探测→无则 node 引擎），179 行里下载/解压/资产矩阵 ~90 行只在 rg-less 新机器生效，而那正是当前挂起的输入。
- 自检: ① 复核 `inflight ??=` 求值顺序与 async 恢复时序，确认外层赋值先于 `downloadRg` 同步段；② 确认 `commandExists` 两分支命中时不经环、正常返回（本机行为即如此）；③ 确认无其它生产方调 `downloadRg`（grep 仅 :86 一处）。
