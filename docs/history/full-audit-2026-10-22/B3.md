### B3-02 [M] 模型调用路径上 params JSON Schema 被 ajv 校验两遍（broker 一层、world-tool 内层再一层）
- 类别: G
- 位置: src/extensions/world-framework/world-tool.ts:18-24,64-76（内层 validators）；重复保证的所在层 src/tools/broker.ts:101,125-140（外层，编译 world-tool 产出的同一 schema）

- 证据: 绕过内层失效的生产入口 0 个：registerTool 全走 broker（runner.ts:614 区域）；`grep -rn "\.run(" tests` 显示直接调 run 的只有测试（如 tests/world-tool-schema.test.ts:63 直调 `tool.run({action:"fail"})`）。两套校验器编译自同一 `action.parameters` 对象（world-tool.ts:24 与 :34 各调一次 closeObjectSchema，schema 源相同）。
- 移除后果: 删内层 validators（保留 `validate` 自定义钩子，它做 trim 非空这类语义检查、非 schema 重复）后：生产模型调用不变（broker 层已拦，返回 not_started+诊断文本）；仅直调 run 的测试需要改走 broker.prepare 或接受行为差异（内层缺失时非法参数直达 action.run）。注意两层失败语义不同（broker=not_started，内层=failed+“可用参数”提示），删内层即统一为 broker 语义——需裁决。
- 处置建议: 保留 broker 层 schema 校验，塌缩删除 world-tool.ts:18-24,64-76 的重复 ajv 层（`validate` 钩子保留）。
- 自检: 已核对 broker oneOf 对 params 的覆盖（required:["action","params"] + additionalProperties:false，覆盖等价）；已核对 world-tool 直调路径确为测试专用；未把 `validate` 钩子（1 个真实消费方 builtins/world-store.ts:31,53,65）误并进本条。
