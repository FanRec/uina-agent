# QQ 五个发现动作的实现审查与修复

日期：2026-10-11，Asia/Shanghai / GMT+08:00。审查对象为未提交的 `people / files / fetch / search / expressions` 实现，以及直接相关的附件定位、呈现和测试。

本文保留当日的缺陷复现与修复记录，文中的测试计数和全量门禁只对应当时工作树。当前工作区的 QQ 离线复核结果见 [QQ World 验收记录](qq-world-acceptance.md)；真实 QQ 行为仍未验证。

## 情况判断

职责划分总体成立：一个 qq facade、十四个动作；文件发现、字节取得和本地检索各有明确成果；普通文件可以交给现有文件消费者。没有证据支持另建资源管理器、索引服务、任务系统或改动 Core。

问题主要集中在状态与成果之间的约束，而非缺少架构层次。原有自动测试证明了主要组合路径，却未覆盖同一对象反复读取、来源位置被替换、失败前的缓存修改及时间表示差异。不能用“原测试通过”推导这些约束成立。

## 已核实的问题与处理

| 位置与优先级 | 原实现问题 | 本轮处理与证据 |
| --- | --- | --- |
| fetch / P1 | 消息分段读取重新使用到达时的旧 URL，覆盖已刷新定位；重复拉取再次触发刷新并追加日志 | 分段定位复用同一附件的已保存证据；第二次调用只读取新 URL，零平台刷新、日志字节不变 |
| facts-journal、fetch / P1 | 仅凭来源位置复用引用；转发同一位置的另一附件能够覆盖旧引用；刷新只核验 type/fileId，漏掉已知 image file 定位 | 同一套附件身份比较核验来源位置、类型和已有 ID/hash；缺少强 ID 时核验已知 file/name。对象替换分配新引用，原引用在重启后仍指向原对象；刷新替换被拒绝 |
| fetch / P1 | 消息点查发生在绑定身份检查之前，部分迟到结果可能先写定位 | 入口及点查返回后核验身份，错账号反例零平台请求、零定位写入 |
| fetch / P1 | 私聊 fileId 缺少 hash 时落入通用 get_file，掩盖专用定位不足 | 缺少专用文件定位明确 locator_unavailable；不猜通用文件路线，不下载 |
| fetch / P1 | HTTP 下载期限没有传入过期 URL 刷新，超时后仍可能提交刷新证据 | 刷新与二次定位共用下载取消信号；超过期限的迟到结果不写定位、不发布资源 |
| expressions / P2 | 校验后续坏行或分页失败之前，已经写入部分表情名称缓存 | 完整载荷及分页成果成功后才更新名称；畸形与非法 cursor 均不污染 browse 呈现 |
| search / P2 | 时间戳 0 被当作未知；归档按 ISO 字符串比较，带偏移的同一时刻被误判 | 时间排序、归档均使用实际时间；覆盖 epoch、负时间、unknown 与偏移格式 |
| search / P2 | 大小写展开后的匹配位置被当作原文偏移，真实命中可能返回空片段 | 将命中偏移映射回展示原文；İ 字符展开反例保留实际命中与截断标记 |
| 查询与发布 / P2 | 平台明确拒绝归为普通失败；文件流写盘失败归为下载失败 | 区分 platform_denied 与 storage_failed；ENOSPC 流式失败清理临时目录，不返回 resource |

其中最初补入的六个反例在修复前全部失败，原有二十六项发现测试通过；修复后原断言继续保留。新增十一项审查测试还覆盖缓存、超时、Unicode、拒绝和流式写盘失败。

另外修正人物名称未知标记，使其与实际 displayName 采用的上下文一致；文件引用要求规范 base64url 编码，继续绑定账号与群。

## 重构思路与落地顺序

1. 先守住对象身份与生命周期。位置负责找到对象，已有平台定位约束刷新；已保存的新证据不能被旧快照回退。下载期限必须约束刷新及发布前的写入。
2. 再收敛失败与成果边界。`platform-query.ts` 集中已有的身份、取消、平台查询和错误映射，避免底层内容观察依赖整组发现动作。它没有状态或独立生命周期。
3. 在原 `resource-fetch.ts` 内集中 `publishDownload`：流式字节、长度和摘要、元数据、目录发布、失败清理由同一个局部函数拥有。动作函数负责选对象与一次地址刷新，不再同时展开全部磁盘流程。
4. 附件身份比较留在 QQ 领域类型旁，由定位日志和刷新共用；检索继续扫描现有 journal，复用现有分页，修正真实时间与文本偏移。不加缓存、索引、后台重试或通用管理框架。

模块深度来自隐藏真实 I/O 细节和维护领域约束，不能用更多类或转发函数代替。目录查询仍直接按领域职责组织，没有将五个动作拆成五套服务。
