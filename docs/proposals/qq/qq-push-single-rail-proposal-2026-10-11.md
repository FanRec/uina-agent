# QQ World 感知极简化提案 v3：哑手机（2026-10-11）

状态：2026-10-11 的 v3 设计记录。当前源码已实现其单书签、focus 流式交付、私聊响铃/群拍肩和 `off/pausedUntil` 核心语义；“待授权”只保留为当时的审批记录，源码不能证明审批来源。旧 §10 合同见[归档版阅读与通知设计](../../archive/qq/qq-reader-notification-design-2026-10-09.md)。当前事实与离线测试见[运行文档](../../current-runtime.md#qq-world)和[验收记录](../../qq/qq-world-acceptance.md)；真实 QQ/模型行为未验证。
谱系：v1（单轨 + 快慢窗口 + 触碰热度）与 v2（门铃/眼睛 + mode 轴 + 预算分配器）均被否。两版共享同一个被否决的预设：**世界是一台注意力调度引擎**。v3 放弃这个预设本身。

## 1. 被否决的根因（覆盖实测与两轮评审）

实测：纸条 → read → 新纸条 → read，digest 退化为多回合 follow，0→1 规则使循环无限重复。
更深层：v1/v2 无论怎么调（窗口、节流、热度、预算、优先级），都是**世界在替 Uina 分配注意力**。人不这样活着：手机不做任何注意力管理——它会响（且只为人也会被响的事响）、会留红点、会在你打开窗口时显示消息，其余全部认知工作由人完成。微信没有智能摘要、没有节流策略、没有态势感知，它是哑的，所以它好用。

## 2. v3 原则：世界零注意力政策

**群是场所，不是消息流**：人不在场，就是不在场——听不见不是缺陷，是场所的定义。红点只是"你不在的时候那里有过谈话"，read 是回来看，focus 是人在场，@ 是有人喊你的名字。场所语义天然成立，无需设计。

**QQ World 不再包含任何"何时让 Uina 看见、看见多少"的判断。** 世界只是一部哑手机 + 一组房间：

- **私聊/temp = 有人对你说话**。说话即入耳：消息正文直接送达（burst 机械合并 1.2s，纯传输层去抖，非政策），推进书签。三个时刻分离：送达立即，注意排队在信箱（忙时等断点，等同兜里震动没掏），回应自由——已阅不回是完整状态，书签推进表示"看见"而非"回复"。
- **群 = 房间里有谈话**。默认你不在场：零注入，红点积累。唯一例外是"有人在喊你"：@self、reply_self、poke → 只拍肩（交付那一句话本身，**不动书签**，红点留着——像锁屏弹一条，聊天界面没开）。
- **focus = 打开的聊天窗口**。声明在场期间该会话一切消息流式可见（免打扰的群开着窗口也看得见），可无限期保持，随时关。驻守粉丝群 = 驻守，她的自由。
- **静音 = 唯一持久配置**。off / pausedUntil 每会话（对人的免打扰/耳塞）。没有 @only/all 模式轴——"想常看某群"是在场行为（focus），不是配置；off + inbox 组合即勿扰与"邮件式查收"，无需新模式。
- **红点永远诚实**。inbox = 聊天列表（引用 + 未读数 + 最近时间），永不催促、永不摘要。"想起来去看"不归世界：她的回看约定（"稍后回来看这个群/这条消息"）用 remind 自订，到期响铃一次、只给查看机会；习惯与牵挂属于主体层，本世界不掺和。

## 3. 剩余机制全表（就这么多）

| 机制 | 语义 |
|------|------|
| 私聊响铃 | 交付该会话全部待读窗口（renderReadWindow 现有格式，含引用前文），推进书签；回复与否由她定 |
| 群拍肩 | @self / reply_self 交付单条消息本身 + 其引用原文；poke 无消息正文，交付一行事件。书签均不动；此后 read 时 @/reply 消息会在窗口中再现（人看锁屏后再点开也会重见，可接受） |
| focus 流式 | focused 会话新消息按 pulse 窗口交付并推进书签；积压不自动消费（进群只看新消息，旧账由 read/skip 显式裁决） |
| read | 点开聊天：顺序窗口消费，推进书签 |
| skip | 已读不看：Math.max 单调推进，审计留痕 |
| browse | 翻历史：只读，绝不动书签 |
| inbox | 看手机：列表 + 红点 + focus 增删 + 静音设置 |
| 内部事件 | follow_up 到期 / 连接断连恢复 / 迟到回执升级：一行式系统通知（手机也有日历提醒和信号图标） |

仅存的两个数字：pulse 1.2s/2s（传输去抖）、响铃窗口最多 30 条/14k 字符（一屏多大）——不是"何时允许看"。手动 `read` 当前默认每页 20 条、上限 100 条，与响铃窗口不是同一上限。recall 相关性改确定性判定：被撤消息已交付（≤ deliveredThrough）或自身发言或被 open 事项引用。@全体成员不再特判。

## 4. 删除清单（相对现役 + v1/v2）

通知账本 notifiedThrough/notifiedAt、ordinary 候选、situationalOverview、qq-backlog、revival、digest/follow/inherit/filter 全部模式、R1/followPressure/suspendedFollow、attention.ts 的 effectiveFollow（focus 直接映射流式）、v1 lazy 窗口、v2 触碰热度/UNTOUCHED_FAST_CAP/批次预算分配器、60 字符触发预览、[QQ 跟读] 标签。预计净删 400+ 行，调度器收缩为"分类（响/不响）+ 去抖 + 合并"，无任何策略分支。

## 5. 此前两个质疑在此模型中的消解

- **轰炸**：群默认零注入，轰炸源不存在。多个私聊同时说话 = 真的收到了 20 条消息，人多时她静音（off），如同人拉黑免打扰——不需要调度器替她挡。
- **困死**：focus 是她开的窗，随时关；群内持续对话需要显式 focus（= 人打开群窗口），一次 inbox 调用，不是启发式续命。世界不制造任何"停不下来"的流。

## 6. 对 §10 合同的偏差登记

| 原合同 | v3 | 理由 |
|--------|----|------|
| 双轨通知/消费分账 | 单书签 deliveredThrough | 红点=消费位，一个账本 |
| push.mode 四态 + filter | 仅 off/pausedUntil | 其余全是注意力政策 |
| focus && mode=follow 才流式 | focus 直接流式，无视 mode | 在场是眼睛，不是门铃设置 |
| 群 0→1 纸条 / 私聊 revival | 私聊全部响铃即开窗；群零注入 | 0→1/revival 是为纸条节流发明的，纸条没了它们失去存在理由 |
| situationalOverview 全局态势 | inbox 红点列表（拉取） | 推送式态势即打扰 |
| R1 退让暂停灌注 | read 窗口预算截断（已存在） | 屏幕尺寸不是政策 |
| recall 30s 时钟窗口 | deliveredThrough 确定性判定 | 证据换时钟 |
| @全体按 at_self 穿透 | 不再特判 | @全体不是对我说话 |
| 通知轨不推进消费位 | 私聊响铃推进；群拍肩不推进 | 响铃即开窗 vs 拍肩，人的语义本来就不对称 |

## 7. 验收场景

1. 私聊连发 3 条 → 一个回合收到 3 条全文；回不回随她。
2. 群闲聊 100 条（无 @）→ 零注入，红点 +N；她想看才 read。
3. focus 粉丝群 → 流式驻场任意时长；unfocus 即安静。
4. 群被 @ → 拍肩一行（消息原文 + 引用），书签不动，红点仍在；read 时重见。
5. mode=off 后被 @ → 静默；inbox 仍计数（免打扰语义）。
6. pause 到期 → 无摘要特例，门铃自然恢复。
7. 对话进行中（私聊）→ 双方消息即说即达，无需任何中间动作。
8. 群内对话 → 她 focus 一次即可连续对话，关闭即止。
9. 已交付私聊消息被撤 → 更正注记；未交付群消息被撤 → 静默。
10. 任何"通知→取件"两段式不复存在。

## 8. 风险与登记

- 群积压可能数日不看——特性非缺陷（人的常态），inbox pendingOnly 可查。
- focus 重启归零，需重新声明（在场是行为状态，重开 App 也是人重新打开窗口）。
- 群拍肩不推进书签导致 read 时重见该消息——登记为可接受。
- control-store v3 迁移：一切 mode/filter → off（原 off）/默认（其余），pausedUntil 保留；一次性。
- scheduler 测试大改；follow/ordinary/lazy 相关测试删除。
- 实现差异仍在：当前每次 `inbox` 都会调用好友与群目录接口，失败虽不阻断红点列表，但不满足本地已知名称优先、在线补全可选的低成本目标。减少重复在线查询仍是未完成事项；测试只证明失败降级，不证明调用成本可接受。
