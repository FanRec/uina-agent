# Uina 扩展运行时重构方案

以 [扩展运行时设计](extension-runtime-design.md) 为目标合同。新装配先在 `src/extensions/next/` 和隔离 Host 中运行。生产切换以 Host 组合根为界，随后删除旧装载路径。

## 1. 实施顺序

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| 单实例 | 用内存定义与 `-e` 单文件发布同一个工具，接真实 Subject 和 Broker。 | 工具回注、失败回收和停用可沿正常入口验证。 |
| 换代 | 捕获请求工具注册项，接通立即停用、定点重载及稳定 Hook 顺序。 | 在途回包、异步启动与停用交错时，旧实例和新实例各自结算。 |
| 组合 | 接入真实输入生产者、可选服务联动和有实际连接或进程的扩展。 | 解除、取消和晚到资源均由实际持有者结算，旁路能力继续运行。 |
| 管理与切换 | 接入包发现、状态持久化、公开 SDK 和交付绑定，替换生产装配。 | 源码与构建入口可用，重启后启用值、业务数据和旧回执仍可核验。 |

## 2. 定义与 SDK

沿用 jiti 和真实路径去重。包清单静态读取，文件包、显式单文件和内置函数归一成同一种定义。用当前公开导出承接 `uina/extension` 的作者类型，构建时输出对应声明。作者运行期通过 `ctx` 使用能力。用独立包 fixture 检查源码及构建装载，通过公开 SDK 的边界规则约束仓内扩展。 [当前 Loader](../../../src/extensions/loader.ts) · [当前公开导出](../../../src/extensions/index.ts)

## 3. 实例、启动和停用

运行时保存定义、启用意愿和当前实例。实例复用 `ResourceScope` 的信号、在途登记和逆序清理。每个 ID 串行结算实例换代，停用受理可立即关闭当前实例的准入并取消，清理等待只约束同 ID 的后续启动。长操作完成时以当前操作及实例引用核对归属。 [现有 ResourceScope](../../../src/extensions/lifecycle-scope.ts) · [当前 Host 装配](../../../src/host/host.ts)

- 初始化的公开注册先暂存，入口返回且实例仍有发布资格时同步安装。各端口沿用精确注销，安装失败撤回已安装项。把 registry 写入与 renderer 通知分开，服务订阅也在安装结算后通知，避免通知异常使已经插入的注册失去注销句柄。
- 关闭承诺先于撤下、通知和 `abort` 建立。待关闭实例立即失去新注册与任务准入。同步回调只检查注册有效性，初始化和已进入的异步工作计入在途。等待它们结算后封存清理栈，晚到的释放句柄在封存前进入该栈。`ctx.start` 只安排一次发布后的 `run`，关闭前尚未开始的函数直接撤下。
- Host 装配完成后打开扩展输入入口，再放行初始实例的后台函数。启动失败的实例单独报告。退出时先关闭准入，同时取消主体活动、直接调用及扩展，再等待结算。沿用现有 CLI 退出协调。 [CLI 退出](../../../src/cli/app.ts)
- 配置文件的合并和原子写入由一个写入序列负责。写入成功后，各 ID 独立推进。命令与嵌入 API 复用该路径，受理与最终结果由同一条操作记录提供。管理命令由 Host 受理并在命令回调之外等待结算。

用控制 Promise 的 fixture 复现启动期间停用再启用，确认旧实例永不发布，新实例在旧资源结算后才取得资源。覆盖撤下后的迟到连接、关闭重入，以及候选导入期间收到停用。初始化失败和观察回调失败分别验证。

## 4. 工具身份与 Hook 顺序

在 `ToolView` 上捕获当次有效定义与注册项。Broker 注册时固定定义、验证器、执行模式与交付身份。`PreparedToolCall` 引用那一笔注册记录，复用同一个 `Tool` 对象重新注册也产生不同身份。根视图与 ScopedToolView 共用 Broker 的身份检查，保留各自的可见范围和调用归属。 [ToolBroker](../../../src/tools/broker.ts)

Subject 将捕获结果随投影传递，投影选择最终名称，定义取自同一捕获。预检重建替换整份请求准备结果。预算、Provider 编码和回包准入使用最终集合。合成帧留在现有上下文工具路径。公开 SDK 只在投影提供工具选择，Provider 的 wire 编码归适配器。 [Subject 投影与执行](../../../src/agent/loop.ts) · [Provider Gateway](../../../src/ai/gateway.ts)

回包时用捕获项准备和分批，现有 Pipeline 保留 Hook、状态、持久记录与回执路径。Broker 进入工具前再次核对注册，包括 `beforeCall` 或启动记录写入的等待间隙。此时失效仍按 `not_started` 结算。保留现有持久启动与结果规则，完成记录和重开恢复用同一会话测试验证。 [Pipeline](../../../src/tools/pipeline.ts) · [会话解释器](../../../src/session/recovery.ts)

Host 在装配定义时确定 Hook 顺序位置，内置保留显式顺序，外部定义按规范化后的来源和 ID 稳定排列。重载继承该位置，实例内按注册顺序。按既有规则分普通和 tail，相同顺序在每次分发时取注册项列表。实际调用前检查注册项，已进入的回调沿用现有合并规则。 [Hook 分发](../../../src/extensions/host.ts)

在 Broker 测试中以同一 `Tool` 对象重新注册，验证旧准备项仍失效。Subject 测试分别挂起模型回包和启动记录写入，在两处撤下旧实现、换上同名新实现，验证旧调用都无法进入实现。用过滤和重建用例检查最终声明与回包准入一致。用现有压缩与 tail 顺序用例加一次单扩展重载，验证 Hook 顺序及分发中撤下、加入的行为。

## 5. 服务、输入与长时工作

具名服务表接替通用 service map、活引用 map 和 World 暴露聚合表。发布先更新目录，再同步通知。订阅只持有当前发布项和解除句柄。解除前取走句柄，绑定回调返回时确认订阅和发布仍有效，已失效的解除句柄当场执行。订阅异常进入原诊断通道。提供者的异步服务调用用同一个 `ResourceScope.run` 记入自身在途工作。先撤下发布及联动，再等提供者的在途工作并释放资源。 [当前服务与共享](../../../src/extensions/runner.ts)

用一组实际可选联动验收，例如语音输出接收端消失时只解除该接收端。测试覆盖两种停用顺序、绑定中发生撤销和已进入的异步服务调用。长时工作选一个需要主动断开才能结束的真实资源，验证取消先于等待。已有 Worker、执行域和持久任务继续由自己的适配器管理，管理层等待实例资源释放结果。 [Live2D Worker](../../../.uina/worlds/live2d/worker/proxy.ts) · [业务任务受理](../../../.uina/worlds/minecraft/executor/facade.ts)

扩展单条输入委托 `Subject.acceptBatch` 返回该条受理结果。带来源的批次在每条准入时检查生产者活性，已有入队、延迟渲染和交付退役沿各自规则结算。测试空闲主体接受输入后生产者即可继续，并覆盖第一条受理后停用、后续条目拒收。 [单条与批量输入](../../../src/agent/loop.ts)

## 6. 数据与生产切换

Host 的部署绑定给扩展提供业务数据目录与交付身份。旧生产者保留 `deliveryKey("builtin:world-framework", "world:<name>")` 对应的 namespace。新生产者使用稳定身份派生。工具结果、输入和查询共享绑定。切换时把旧显式覆盖和仍需使用的缺省启用项转换成新部署选择，分别核对工作区和 Profile。 [回执合同](delivery-receipts.md) · [现有重启测试](../../../tests/delivery-host.test.ts)

切换以源码和构建入口的隔离验收为准。用默认 Vitest 池覆盖 jiti，验证公开 SDK fixture、首个请求、工具回注、文件事件和临时数据重开。跨进程行为用真实 Worker 或进程验证，真实设备及外部服务沿能力自己的入口验证。

生产组合根换到新装配后，删除 `world-framework`、旧入口类型、`world_store`、独立扫描和状态管理。同步更新构建资源、边界规则、开发入口和当前运行时说明。保留切换前的可运行构建和原启用设置，回退前结算当前实例及外部资源。
