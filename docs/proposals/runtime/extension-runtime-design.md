# Uina 扩展运行时设计

## 1. 产品与职责

操作者用 `/extensions` 管理本地扩展。主体使用业务工具办事，连接、播放、发送与查询由能力本身提供。一个工具可以在离线时照常解释状态、提供连接入口。扩展作者从一个 `activate(ctx)` 开始，同一个入口用于脚本、包和内置能力。

| 所有者 | 职责 |
| --- | --- |
| Host | 装配主体、会话、Provider 和扩展，提供输入与管理入口。每个 Host 有一套扩展运行时。 |
| 扩展运行时 | 发现定义，按启用意愿启动、停用和换代，给出诊断。 |
| 激活实例 | 持有本次激活的注册项、取消信号、在途工作和释放句柄。 |
| 能力端口 | Broker 校验并执行工具。Hook 与事件沿各自合同分发。服务表管理具名发布和订阅。命令及 renderer 接到消费者。 |
| 扩展 | 拥有业务状态、外部连接、进程与执行结果，负责资源释放和业务恢复。 |

扩展 ID 用于装配和管理。进程内所有权归具体激活实例。业务数据目录和持久交付身份由 Host 绑定，可以跨扩展重组延续。

## 2. 编写与发现

```ts
import type { ExtensionContext } from "uina/extension"

export default function activate(ctx: ExtensionContext) {
  ctx.tools.register({
    def: {
      type: "function",
      function: {
        name: "hello",
        description: "返回一条问候",
        parameters: { type: "object", properties: {}, additionalProperties: false },
      },
    },
    run: () => ({ result: "你好", status: "succeeded" }),
  })
}
```

把文件保存为 `hello.ts`，用 `pnpm start -e ./hello.ts` 装配到本次运行。单文件使用真实路径派生开发 ID。部署包在 `package.json` 的 `uina.extension` 中声明稳定 `id`、`entry`、`apiVersion` 和 `description`，可以设置 `defaultEnabled`，文件包缺省关闭。

Host 合并内置描述符、项目 `.uina/extensions/`、用户配置根的 `extensions/` 和显式 `-e`。目录只扫描一级包，读取清单即可列出禁用项。`-e` 可指向包目录、声明入口或单文件。按真实入口去重，多个定义声明同一 ID 时报告来源；已发布的实例继续服务。启用意愿按本次显式选择、保存设置、定义默认值的顺序确定，运行中的管理动作可以更新它。

扩展按本地受信任代码运行。包在入口求值前检查 SDK 版本。模块顶层声明代码，取得资源从 `activate` 开始。Provider 通过现有 Provider 合同由 Host 启动装配，作者通过公开模型端口使用已装配的模型。

## 3. 激活与释放

### 发布

`activate` 可以同步完成，也可以等待发布所需的本地初始化。工具、Hook、事件、命令、renderer 和服务的首批注册在入口成功返回后安装。安装失败时按已有注销句柄撤回本次注册。服务订阅及展示通知在安装结算后运行。实例发布后可以继续增删单项贡献。

取得外部资源后用 `ctx.onDispose(fn)` 登记释放。需要在发布后开始的观察、连接和预热使用 `ctx.start(signal => …)`，登记后立即返回。初始装配时，Host 等本次选中的入口逐一结算，记录各项失败，再打开输入入口并放行已发布实例的 `ctx.start`。交互、一次性和嵌入模式使用同一就绪口径。提前提交的输入得到拒收结果。

### 停用和重载

停用受理时关闭实例准入，撤下公开注册，解除服务联动，发出取消信号。关闭承诺在这些动作前建立，重复关闭共享一次结算。已取得但还未调用的注册项在进入时复核有效性。已进入的工作观察取消并按原合同结算。

等本次初始化和已进入的工作结算后，逆序释放资源。在这之前，受跟踪的工作迟到取得的资源仍交给当前实例清理。需要关闭连接才能退出的工作在收到取消时主动断开。实例在结算期间显示 `stopping`，无关实例独立推进。

重载先导入并校验候选入口，导入失败时旧实例继续服务。候选检查通过后停旧实例，清理成功才启动新实例。启动失败释放本次资源并报告结果。停用受理后，正在初始化的实例即刻取消。再次启用等待旧实例结算，并以新实例启动。候选导入或初始化完成时，按当前实例和最新启用意愿决定是否发布。

Host 关闭先停止受理管理操作和输入，向 Subject、直接调用及扩展实例发出取消，等待结算后关闭会话。进程退出由 CLI 协调。独占资源的退役与重新取得由拥有它的适配器核验。

## 4. 主体调用与 Hook

Broker 中每个工具名有一个生效注册。重名报告双方来源，部署据此选择实现。同一次注册的工具定义固定。

每次模型请求从当前 ToolView 捕获定义和精确注册项。投影选择其中的工具，最终选择同时用于预算、Provider 编码与回包准入。预检重建使用新投影和对应的捕获。合成回执工具保留既有协议。公开 SDK 的工具选择位于投影阶段，Provider 侧开放请求头变换和响应观察。

模型回包只准备本次声明的注册项。Broker 在实际执行前核对同一项仍然有效，哪怕异步前置处理或启动记录写入期间发生了换代。未声明、已撤下或尚未进入即取消的调用返回 `not_started`。程序调用使用当前注册。已进入的调用按实际结果结算，外部效果无法确认时返回 `unknown`。

每次 Hook 分发按组合顺序取得当次注册项列表。保留普通与 tail 相位、内置压缩顺序及原有合并规则。相同定义重载后使用原来的顺序位置，实例内按注册顺序执行。分发中撤下的项在进入前跳过，新注册在下次分发生效，已进入的 handler 按既有 Hook 合同结算。事实观察使用原事件出口。

## 5. 服务与长时工作

`services.publish(key, port)` 发布具名契约。每个名称只有一个有效发布项，跨包契约的破坏性变更使用新的主版本键。`get(key)` 用于即时访问，`watch(key, bind)` 用于随服务出现和消失建立联动。服务对象由契约定义，复制、握手和协议转换留在实际的适配器边界。

`watch` 从当前发布开始。`bind` 同步接线，可返回一个同步解除句柄，例如某个工具的注销。先解除旧绑定，再绑定新发布。提供者停用时，目录先撤下发布，订阅方完成解除后，提供者再释放资源。消费者停用也会解除其当前绑定。绑定或解除的异常归订阅方报告，其余订阅继续结算。动态设备列表由业务端口表达。

跨扩展订阅或租用返回自己的释放句柄。异步服务方法若使用提供者持有的资源，以提供者的 `ctx.run` 纳入在途结算。`ctx.run` 与 `ctx.start` 使用同一实例作用域。解除联动时取消订阅方为该绑定启动的工作。必须共同初始化和退役的实现可以直接组合在同一个扩展。

实例作用域拥有监听循环、连接维护和本地 Worker。需要独立于一次模型回合或跨重启继续的业务任务由业务执行域拥有。工具可以报告受理和任务句柄，后续查询、取消、结果投递与恢复由相应能力处理，沿用已有工具续跑与交付合同。扩展停用释放本实例的资源和交付连接，任务终态以业务域的事实为准。

## 6. 管理、输入与数据

本机 `/extensions list`、`show <id>`、`enable <id>`、`disable <id>`、`reload <id>` 与嵌入 Host 使用同一管理入口。`/reload` 重载当前启用的文件扩展。操作区分受理和最终结果。记录展示启用意愿、`disabled`、`starting`、`active`、`stopping` 或 `failed` 实际状态和最近错误。`active` 表示能力已发布，业务健康由能力自己的入口报告。

启用覆盖值保存在项目 `.uina/extensions.json` 或 Profile 的状态根。设置写入后才受理持久启停。开发脚本的启停属于当前进程。Host 注入包目录、工作目录和业务数据根，业务扩展读写自己的配置与存储。

单条与批量扩展输入返回逐条受理结果。每条准入时检查生产者仍活动，已经受理的条目沿原邮箱规则结算。已入队的普通正文由主体持有，依附旧实例的延迟渲染和带回执尝试沿既有退役规则处理。

工具结果、输入和回执查询共用 Host 绑定的稳定交付身份。canonical append 决定 committed，外部效果和任务状态由业务事实决定。
