# Uina / MO 动态筛选与表演设计

日期：2026-10-11（Asia/Shanghai）。状态：部分设计已进当前 MO 目录；2026-10-14 复核有 17 个已发布动作与四段 sway 短句，实际名称包括 `spin`、`close_up`，不同于本文候选的 `screen_spin`、`face_closeup`。`freeze`、`angry_pout` 和偏嘴 `smirk` 未发布。当前曲线内容测试只证明编译/运行边界，不证明动作观感；真实 MO/VTS 画面未验收。

范围固定为当前 MO 模型。允许调整动作内容、运行机制、程序 rig 适配和整模屏幕位姿；不修改模型网格、贴图、变形器、物理文件、表情资源或 VTS 保存绑定。本稿不覆盖已确认的 World 边界规范；需要改变执行语义的地方明确列为后续提案。

按用户要求，音乐律动不进入本轮目录或实现计划；Live2D 不新增播放器、音频分析或节拍时钟依赖。轻晃由自身动画时间驱动，思考沿用宿主已有状态，现有语音口型接缝保持原职责。

当前程序接入九轴，但实际模型保存配置还已有 Brows、MouthX、CheekPuff 等绑定。九轴不是模型全部能力的证明。利用这些已有绑定属于补程序接入，不是补模型；本稿因此保留偏嘴坏笑与气鼓鼓的设计，而不把所有未接入面部动作一概判为模型不支持。

## 1. 判断与筛选

这份清单的数量本身可以接受，问题在于混合了短动作、持续状态、情绪解释和算法名字。Uina 应拥有有区别的表现词汇；一个动作可以协调多个部位，单一职责不等于每根轴一个工具。

筛选以三个问题为准：静音看画面能否分辨？当前模型能否表达其关键姿势？与另一个候选相比，是否只是名称不同？

建议保留十二个参数手势、四个空间手势、三个头部基准姿态（包含默认）、三个持续表情，以及现有注视目标。背景行为只保留轻晃和宿主驱动的思考；呼吸维持现有 VTS 来源。这里的数量是本轮内容判断，不是工具容量限制。

| 原候选 | 决定 | 最终表现及理由 |
| --- | --- | --- |
| 点头 | 保留 | 点头应声 `nod`；垂直的一次确认 |
| 摇头 | 保留 | 摇头否认 `shake`；左右两次不同轻重的摆动 |
| 单眨眼 Wink | 保留 | 俏皮眨眼 `wink`；一侧闭眼、另一侧保持可见 |
| 歪头 | 保留 | 侧歪打量 `curious`；侧倾并停下来，不做左右摇摆 |
| 得意昂头 | 保留 | 得意昂头 `chin_up`；先抬下巴，再把目光落回观众 |
| 雀跃弹跳 | 保留空间版 | 雀跃一弹 `joy_hop`；整模上下移动，不能冒充屈膝跳跃 |
| 傲娇甩头 | 保留 | 哼一下 `head_toss`；快转开、慢回头，中间偷偷看回来 |
| 警觉/惊吓/惊讶 | 分成同一反应家族的三个版本 | 凝神警觉 `alert`、吓一跳 `startle`、惊讶一顿 `surprise`；区别来自方向、冲量和停顿，而非三个表情贴图 |
| 360 度旋转 | 作为罕见特技保留 | 转个圈 `screen_spin`；屏幕平面整模转圈，不是转身展示背面 |
| 大头贴 | 保留空间版 | 贴脸特写 `face_closeup`；脸部进入特写构图 |
| 暗中观察 | 保留空间版 | 边缘探头 `edge_peek`；从画面边缘露出部分脸 |
| 默认态 | 保留基准 | 自然站定 `rest`；不单独算一种表演 |
| 身体前倾凑近 | 不保留“身体前倾”承诺 | 凑近交给 `face_closeup`；没有独立躯干前倾控制 |
| 自闭害羞 | 收敛为姿态与组合 | 垂头收起 `tuck`；“害羞”是姿态、回避、回看组成的演出 |
| 身体后仰 | 不保留“身体后仰”承诺 | 仰头放松 `head_back`；只使用现有头部及随动，不声称弯腰 |
| 灿烂笑 | 保留 | 明朗笑 `smile`；高嘴形、较开的双眼 |
| 坏笑 | 保留 | 偏嘴坏笑 `smirk`；半眯眼与略偏的一侧嘴形；偏嘴使用模型已有 MouthX 绑定 |
| 生气 | 保留轻喜剧版 | 气鼓鼓 `angry_pout`；现有眉毛态度与鼓嘴绑定提供新轮廓；不承诺怒纹、尖牙或激烈愤怒 |
| 呆滞 | 改成短事件 | 当场卡住 `freeze`；依赖动作突然停顿，不制造“空洞瞳孔” |
| 委屈 | 筛掉独立表情 | 当前不能确认能独立呈现委屈眉、泪眼、下弯嘴；共用 Brows 的抬眉可能更像惊讶，不发布名不副实的 `sad` |
| 疑惑 | 合并 | `curious` + 注视目标；不再增加近似的疑惑脸 |
| 害羞 | 合并 | `tuck` + `avert_down` + `glance`，可搭配较轻的笑 |
| 偷瞄 | 保留短事件 | 偷瞄一眼 `glance`；有回到原目标的过程 |
| 正中央 | 保留目标 | `screen`；与 `user` 的既有坐标语义分开 |
| 乱瞄 | 筛掉独立动作 | 默认微漂移即可；大幅随机扫视没有清楚的观看意图 |
| 视线回避 | 保留目标 | 既有 `avert_down/left/right`；情绪由其它部件提供 |
| 翻白眼 | 降为现有能力 | 无语望天 `eye_roll`；上望与慢回落，不承诺眼白完全翻出 |
| neuro 式不倒翁 | 保留律动意图 | 轻轻晃着 `idle_sway`；较慢的侧倾，关键反应出现时让位 |
| 听歌卡点律动 | 按用户要求筛掉 | 不新增音乐系统依赖，也不提供假卡点的替代动作 |
| 思考 | 保留背景行为 | 找思路 `thinking`；视线停留、轻歪头、偶尔重新定向 |
| 质数异频呼吸 | 筛掉独立模式 | VTS 已拥有呼吸；互质周期不等于自然，也不值得作为动作名称 |

`greeting` 的现有内容只有头与嘴，可由 `nod` + `smile` 组成；不再以 `wave` 暗示挥手。旧 `brighten` 与新设计的 `smile` 收敛为一种明朗笑。名称迁移属于未来实现，本轮不改目录或旧调用。

## 3. 全局表演语言与数值约定

目标气质：轻、敏捷、有观看意图；熟悉观众时可以俏皮，惊讶时敢于停住。平静时不需要不断证明自己在动。

- 每个手势都有一个能认出来的主姿势。眼睛、头和整模移动分别承担引导、态度和构图；不用所有部件同时到峰值。
- 普通转向的视线目标领先头部约 60–100ms。惊吓是例外：先闭眼/收缩，再睁眼确认。这里的时间是显示目标，不是已经测到的链路延迟。
- 点头与摇头按当前姿态作增量；表情保持相对独立。需要特定眼睑或目光的短动作临时拥有那些轴，结束交还当时有效的表情/注视。
- 明显动作使用快入、可读停顿、慢收势；短动作也留出关键姿势，而不是连续往返的正弦。
- 幅度变化围绕语义进行，例如赞同的点头更浅、强调时更深。可在重复时采用有界的轻重、时长、方向变化；不随机改变一项动作的关键姿势。
- 呼吸与头部微晃不能同时堆满。前景动作到来时背景在约 150–250ms 内降低，结束后约 350–600ms 恢复。
- 正常讲话让口型继续工作。`speech="exclusive"` 在当前实现只压制嘴型，不暂停音频，不可用它制造假静默。

数值使用当前逻辑轴的创作单位：`Y=head.yaw`，`P=head.pitch`，`R=head.roll`；`G=(gaze.x,gaze.y)`；`EL/ER=两侧眼睑开度`；`F=mouth.form`；`O=mouth.open`。

当前九轴范围是 Y ±12、P/R ±10，G ±1，EL/ER/F/O 在 0–1。它们不是已测量的画面几何角度。下文左右方向先按观看效果描述：当前 `gaze.x` 标尺与眼球参数符号相反，不能直接以参数正负猜测画面方向。

补程序适配的模型专用控制建议为 `mo.brows.attitude`、`mo.mouth.skew`、`mo.mouth.puff`。只有一个 Brows 输入：其已有扇出包括两侧眉高度、两侧眉形和 Param47，而且输出标尺不同；不能冒充五个独立旋钮。下文新控制幅度用经过标定的舒适范围比例描述，不把未知中性或形状方向写成已确认值。

普通动作以 |Y|≤8、|P|≤6、|R|≤6 为起始设计区间，为姿态叠加留下余量；强反应可短时接近 Y=9、P=7。动作遇到已有姿态时要缩小增量，避免最终裁剪把关键帧压平。以下数值都是首版作者目标，不能代替真实画面调节。

时间轴以可见表演为目标。当前存在头部二阶弹簧、80ms 面部平滑、默认 120ms 入场与 250ms 退出；直接把下表写成关键帧会改变峰值、停顿和先后关系。实现时应沿现有管道调节，不再叠一层无依据的滤波。

## 4. 十二个参数手势：整体及分解设计

### 4.1 点头应声 `nod` — 约 650ms

整体：短促、明确的一次赞同，有轻微回弹，不做连续鞠躬。

| 时间 | 分解 |
| --- | --- |
| 0–100ms | G 保持原注视；P 轻提 +0.8，作为准备 |
| 100–280ms | P 下压至 Δ−5.5；眼睑保持，嘴不参与 |
| 280–350ms | 关键姿势短留，降低速度 |
| 350–480ms | P 回弹至 Δ+1.2，幅度显著小于下压 |
| 480–650ms | 回到当前基准，交还控制 |

有 `attention=user` 时不额外写 gaze.y，让头姿补偿维持注视。正在看屏幕或其它目标时沿用该目标。当前 nod 同时写 gaze.y 会把“点头”带成“往下看”，建议移除这种无意图的耦合。

### 4.2 摇头否认 `shake` — 约 820ms

整体：第一摆明确，第二摆较轻，收回不再做第三次同强度摆动。

| 时间 | 分解 |
| --- | --- |
| 0–120ms | Y 从基准转向一侧 Δ+5；R 反向约 −1.2 |
| 120–300ms | Y 越过基准至 −6；R 到 +1.8 |
| 300–460ms | 第二次较轻地回到 +3.5 |
| 460–600ms | 约 100ms 减速停留，再回基准 |
| 600–820ms | 小幅残余收势，无额外左右反复 |

目光尽量留在原对象，不随头满幅摆动；口型保持。与 `head_toss` 的区别是“左右否认”而非“转开后拒绝看你”。

### 4.3 俏皮眨眼 `wink` — 约 620ms

整体：清楚的一侧闭眼，轻歪头作为陪衬；观众应当能看见另一只眼。

| 时间 | 分解 |
| --- | --- |
| 0–90ms | 目光落到观众，R 开始侧倾 Δ2 |
| 90–150ms | 一侧眼睑从原值到 0；另一侧保持约 0.9 |
| 150–270ms | 单侧全闭保持；F 可短暂提升到约 0.6，不改 O |
| 270–430ms | 闭眼侧重新睁开，慢于闭合 |
| 430–620ms | R 和临时 F 交还原状态，眼睑明确恢复 |

第一版固定角色偏好侧，不因随机镜像失去辨识。需要协调生理眨眼：现有最终乘法调制可能把 Wink 变成双闭眼。严格单侧效果需要程序修正；不是增加模型通道。

### 4.4 侧歪打量 `curious` — 约 1,100ms

整体：视线先落向对象，头侧倾后停住，像在等一句解释。

| 时间 | 分解 |
| --- | --- |
| 0–100ms | 目光定向，不做大幅扫动 |
| 100–360ms | R 到 Δ5.5，P 到 Δ+1；Y 只加约 1 |
| 360–750ms | 维持清楚侧倾，眼睛正常打开；嘴沿用当前神态 |
| 750–1,100ms | 更慢地回原姿态、原目标 |

不默认绑定笑嘴。这样疑惑、好奇和温柔倾听都可由 expression/attention 组合出来，而不是目录里塞三条近似歪头。

### 4.5 得意昂头 `chin_up` — 约 1,100ms

整体：下巴往上，但目光随后压回观众，形成“我就知道”的反差。

| 时间 | 分解 |
| --- | --- |
| 0–140ms | 目光稍上移，作为起意 |
| 140–360ms | P 到 Δ+5，R 约 −1；头不向左右摆 |
| 360–760ms | 目光落回观众；抬下巴保持，身体随现有绑定变化 |
| 760–1,100ms | 放下下巴，平缓收势 |

`smirk` 为可选组合，动作本体不永久改表情。与 `head_back` 的区别是有“抬下巴→重新看你”的事件节奏。

### 4.6 哼一下 `head_toss` — 约 1,250ms

整体：先拒绝看你，再忍不住偷瞄；“偷偷回来”的目光是性格记号。

| 时间 | 分解 |
| --- | --- |
| 0–90ms | G 快速移开到一侧约 0.55 |
| 90–320ms | Y 向该侧到 Δ8，P +2，R 约 2；头比眼晚到 |
| 320–650ms | 停在转开的姿势；嘴不强制变笑 |
| 650–790ms | 头仍朝外，G 短暂偷看观众 |
| 790–900ms | G 再移开，保留“装作没看”的一拍 |
| 900–1,250ms | 头慢回基准，目光交还有效目标 |

不称真实甩头发；发丝只沿模型已有物理随动。与 shake 的轮廓、方向和停顿明确不同。

### 4.7 凝神警觉 `alert` — 约 1,050ms

整体：先停下原来的松弛，再朝一个方向注意。既没有跳起，也没有张嘴惊叫。

| 时间 | 分解 |
| --- | --- |
| 0–100ms | 减低背景晃动；眼睑从原状态向 0.95 打开 |
| 100–190ms | G 定向侧边约 0.55 |
| 190–430ms | Y 转到 Δ4，R 轻倾 1.5；身体跟随现有绑定 |
| 430–760ms | 凝住方向，嘴型不变 |
| 760–1,050ms | 注意解除，缓慢交还 |

这是显式调用时的表演语义，不能仅靠动作代码声称已经听见真实环境声音。

### 4.8 吓一跳 `startle` — 约 900ms

整体：快收缩、睁眼确认、带余势回落。与 surprise 的区别是明显冲量。

| 时间 | 分解 |
| --- | --- |
| 0–110ms | EL/ER 到约 0.25，P 快速 −2.5；模拟条件反射的收缩 |
| 110–290ms | 眼睛到 1；P 反向到 +5，R 向一侧约 2.5 |
| 290–430ms | 静默时 O 可到 0.2–0.3；短暂确认方向 |
| 430–610ms | P 回落到 −1，形成比主冲量弱的余势 |
| 610–900ms | 回基准；O 释放，讲话时始终交给语音混合 |

第一版只用参数轴，避免把同一个效果绑定到尚未可靠的空间退缩。需要为急反应选择实际合适的入场/弹簧配置；目前 runtime 没有把动作作者的特殊播放选项透传出去。

### 4.9 惊讶一顿 `surprise` — 约 1,300ms

整体：目光锁定、嘴略张、头保持，读出“啊？”而不是受惊弹起。

| 时间 | 分解 |
| --- | --- |
| 0–150ms | 视线锁到对象；EL/ER 到 1 |
| 150–340ms | P 轻提 Δ2；静默时 O 到约 0.22，F 降到接近中性 |
| 340–850ms | 主姿势停留；不加入循环晃头 |
| 850–1,300ms | 嘴与头分开收势，嘴先合、头后回 |

1 已是眼睑上限，不能通过写 1.3 制造睁得更大。也不承诺模型没有的圆 O 嘴。表演靠中断原动势与停顿建立对比。

### 4.10 偷瞄一眼 `glance` — 约 800ms

整体：眼先动，头只稍跟一点，然后回原来的观看对象。

| 时间 | 分解 |
| --- | --- |
| 0–100ms | G 从原目标移向侧边约 0.45–0.6 |
| 100–250ms | Y 仅跟 Δ1.5，避免变成转头 |
| 250–480ms | 短留；眼睑约 0.85，不自动加笑 |
| 480–620ms | 眼先回当前有效 attention |
| 620–800ms | 头跟回；交还临时眼睑 |

方向可以由两条作者变体给出，第一版不必对外重复发布近似名称。return 使用当时有效目标，不能写死回正中，更不能覆盖调用期间新设置的 attention。

### 4.11 无语望天 `eye_roll` — 约 1,200ms

整体：半眯眼稍等、目光朝上、慢慢回落。它是有态度的望天，不是解剖意义的翻出眼白。

| 时间 | 分解 |
| --- | --- |
| 0–180ms | 眼睑到约 0.55，F 不额外变笑 |
| 180–320ms | G.y 到约 +0.7，G.x 沿一小段侧弧移到 ±0.15 |
| 320–660ms | 上望保持；P 最多 +1，避免变成昂头 |
| 660–1,000ms | G 慢回原目标；头保持轻静 |
| 1,000–1,200ms | 眼睑交还原表情 |

当前 gaze.y 只映射到眼球参数的约 ±0.52，不能保证上望会露出足够眼白。若真实画面只像往上看，中文名保持“望天”。

### 4.12 当场卡住 `freeze` — 约 900ms

整体：已有动势突然减到几乎没有，正视半拍，再用一次眨眼退出。

| 时间 | 分解 |
| --- | --- |
| 0–130ms | 从当前呈现值收住头和目光；不骤然吸回全零 |
| 130–650ms | 保持头、目光、眼睑；静默时嘴形近中性、嘴闭合 |
| 650–820ms | 一次双眨眼作为“恢复处理”的记号 |
| 820–900ms 及退出 | 平滑交还背景与注视，不跳变 |

这需要捕获当前呈现姿势并协调眨眼/背景；仅写 baseline-offset 的全零轨道不会冻结。VTS 呼吸和物理仍可继续，因此目标是“可见主动层凝住”，不是所有像素完全静止。讲话中保留嘴型，只呈现“凝住看你”；完整喜剧停顿适合已有话音间隙。

## 5. 四个空间手势

全部属于命名 motion，经 express/cue 同一入口执行；不恢复独立 spatial/flip 工具。

构图幅度以实际渲染画面宽高 W/H 表达，缩放以可见大小比表达，不直接当成 VTS `size` 数值。VTS 的位置/大小参数需要在运行侧换算与标定，尤其不能把 `size += 0.15` 当成放大 15%。这类坐标标定是动作代码/数据，不修改模型内容。

### 5.1 雀跃一弹 `joy_hop` — 约 1,100ms

整体：一个主弹、一个小余弹，整模上下形成清楚轮廓；头、眼和嘴晚一点到峰值。

| 时间 | 整体位姿 | 参数动作 |
| --- | --- | --- |
| 0–160ms | 下移约 0.01H，准备起弹 | P −2；不缩放冒充身体压扁 |
| 160–340ms | 上移到基准上方约 0.045H | P 回到 +1；笑可沿用 expression |
| 340–500ms | 越过顶点下降 | R 约 2；在顶点后才做约 100ms 的笑眼闭合 |
| 500–650ms | 回到基准略下方 0.004H | P 轻下压 |
| 650–800ms | 余弹上移约 0.015H | 主弹约三分之一的幅度 |
| 800–1,100ms | 归位 | 头和眼睑平缓交还 |

不宣称有膝盖蹬地、重心真实跳起或身体挤压。此版是可爱的皮套整模弹动，现有模型足够，当前单段空间执行器不足。

### 5.2 贴脸特写 `face_closeup` — 约 1,800ms

整体：先把目光放到观众，再进入脸部特写，在最近处停一拍，缓缓退回。

| 时间 | 分解 |
| --- | --- |
| 0–140ms | 看向观众；略微抬下巴，避免脸部缩放后看不到眼睛 |
| 140–530ms | 缩放并补偿 x/y；以脸部锚点进入特写，目标脸高约占可用构图高度的 55%–65% |
| 530–1,100ms | 特写停留；R 可加入 2–3 的小侧倾，不持续晃动 |
| 1,100–1,800ms | 慢于进入地退回；保持观看对象，最后归位 |

保留两眼、嘴和下巴的可读空间；以当前画面能容纳的大小为准，不强行越过画面边界。需要脸部锚点和真实缩放转换；根节点居中放大可能把脸放到画面外。动作本体不等于身体前倾。

### 5.3 边缘探头 `edge_peek` — 约 2,200ms

整体：从边缘露出一部分脸，眼睛看向画面里面，头稍歪，再缩回并归位。

| 时间 | 分解 |
| --- | --- |
| 0–450ms | 整模移动到选定边缘外侧，减少身体露出 |
| 450–800ms | 向画面内探入，约露出 35%–50% 的脸宽；至少露出一只完整眼睛 |
| 800–1,400ms | G 指向画面内，R 约 4；头轻缓跟进，姿势停留 |
| 1,400–1,700ms | 整模退到边缘外侧 |
| 1,700–2,200ms | 回原构图，归位后交还 |

第一版只支持一个作者选好的画面边缘；对称变体不是必要条件。需要视口和脸部锚点，不能只给固定 x 偏移并声称一定露出眼睛。效果来自画布裁切，不要求新的遮罩/墙体/手臂资源。

### 5.4 转个圈 `screen_spin` — 约 1,700ms

整体：短准备、完整一圈、减速落定；作为庆祝或喜剧标点，频繁使用会破坏角色重量感。

| 时间 | 分解 |
| --- | --- |
| 0–180ms | 小幅反向预备约 −6°；头回到舒适区 |
| 180–1,250ms | 连续沿同一方向完成屏幕平面一圈；四个象限都应可见；中段最快 |
| 1,250–1,450ms | 减速至原朝向附近，小余势约 +4° |
| 1,450–1,700ms | 回原朝向与构图，核实基线 |

围绕可见形象的合适旋转锚点转，必要时补偿位置，防止绕远处原点转成大范围公转。不要保持夸张歪头再叠满整模旋转。

当前发一次 `base.rotation + 360` 不能证明途中转过一圈。API 插值、角度归一化和最短路径行为需要真实 VTS 核对；执行器必须表达多段连续进展，而非只核对最终角度模 360 相同。它保留为罕见内容候选，实现条件不满足时不宣称已完成。

## 6. 持续姿态、表情和注视

这些是独立的基础积木。持续槽不应同时把头、眼、嘴全部占住。

### 6.1 头部基准姿态

| 名称 / ID | 整体设计 | 分解与进入退出 |
| --- | --- | --- |
| 自然站定 `rest` | 默认可接纳其它动作的基准 | Y/P/R=0；只负责头部，不写 gaze、眼睑或嘴。约 600ms 平缓回基准 |
| 垂头收起 `tuck` | 下巴收起，头偏开一点，形成与默认明显不同的轮廓 | P≈−5、Y≈−2、R≈+2。约 650–800ms 进入，约 600ms 退出；害羞所需的目光回避由 attention 另设 |
| 仰头放松 `head_back` | 下巴抬起、轻侧倾，像拉开一点心理距离 | P≈+4.5、Y≈+1、R≈−2。约 750ms 进入，约 650ms 退出。不是独立躯干后仰 |

身体只沿当前头部绑定及物理随动；不能为躯干另编一个延迟值。现有 `lean` 的 P=3、G.y=0.3 不是身体前倾；现有 `attentive` 与默认差别较小，不再作为主要可见种类。

目录应有明确的 `rest` 项。当前工具提示里的 neutral 是引擎回落语义，不等于可以直接传入一个尚未登记的 `name="neutral"`。

### 6.2 持续表情

| 名称 / ID | 整体设计 | 分解、说话与边界 |
| --- | --- | --- |
| 明朗笑 `smile` | 明显笑嘴，双眼较开，适合正常聊天 | F≈0.9，EL/ER≈0.85–0.95；不固定 O。约 350–500ms 显出、约 450–600ms 退回 |
| 偏嘴坏笑 `smirk` | 半眯眼、笑嘴与轻微偏嘴构成反差 | F≈0.65–0.75，EL/ER≈0.45–0.55；通过已有 MouthX→Param122 增加舒适歪嘴幅度的约 20%–30%。不承诺单侧眉挑起。约 450–600ms 进入，退出略慢 |
| 气鼓鼓 `angry_pout` | 嘴鼓起、眉压低、眼睛稍收；可爱的不满 | F 接近 0，EL/ER≈0.7–0.8；puff 取舒适范围约 55%–70%，Brows 使用实际可读为不满的共同姿势；不写头或视线。不承诺泪、怒纹、尖牙 |
| 解除神态 `clear_face` | 清除持续表情的意图 | 槽值为空，交还 rig 中性及其它当前来源；不是第四种独立脸 |

MO 的 mouth.form 标尺记录了笑眼随动，因此 F 与眼睑的组合必须在真实画面确认，不能当成完全独立的面部形变。smirk 的歪嘴是模型已有参数“歪嘴”的输入接入，不是凭空生成新嘴角；实际幅度与叠加效果仍未验证。表情若最终难以区分，应减少其中一种；不靠更换名称维持虚假的丰富度。

气鼓鼓分解：0–180ms 嘴的笑意收起；180–400ms 眉毛态度进入，眼睛稍收；400–650ms 嘴逐渐鼓起；650ms 后形成可读主姿势。退出时先用约 250ms 放松鼓嘴，再用约 350–500ms 放松眉眼。说话时维持正常 O，鼓嘴适当降低，静默后再恢复，避免每个音节开口都像嘴部变形故障。当前槽只有统一线性过渡，完成这样的分部位进入/退出需要基准过渡内容；单纯扩 rig 只能得到简化同时进入版。

若现有 Brows 扇出在真实 MO 上只表现为抬眉、无法读出不满，保留这个可见姿势但把名称收敛为“鼓嘴”，不硬称完整生气脸。它比“委屈脸”更值得保留，是因为鼓嘴提供了独立的新轮廓，而不是情绪名称更多。

表情不写 head 或 gaze。也不靠持续 O=0.3 冒充笑，因为它会在无声音时永久张嘴。当前 expression/posture 的默认槽过渡均约 600ms，上述逐项时长需要运行侧选择或保留 600ms 的近似版本；hold_ms 从进入开始倒计时，不是关键姿势完成后再计时。

### 6.3 注视

| 目标 | 表现职责 | 使用方式 |
| --- | --- | --- |
| `user` | 看向观众 | 当前瞄准坐标 (0,0.15)；头转动后补偿眼球。没有真实观众位置追踪 |
| `screen` | 看向正中 | 当前坐标 (0,0)；不是“在真实屏幕上读到某一段文字” |
| `avert_down` | 垂眸 | 当前坐标 (0,−0.6)；可与 tuck 组合 |
| `avert_left/right` | 向侧边回避 | 当前坐标 (∓0.8,0)；实际画面方向依 rig 标尺判断 |

目标是持续“看哪里”；`glance/eye_roll` 是“怎样转移目光”的短事件。当前 setAttention 直接换 aim，缺少转移曲线：计划加入约 80–140ms 的短移视与目标停留，避免以连续匀速眼球滑动代替一次定向。重新设置、到期或动作退出时都从当前呈现值交接。

有界微漂移可以保留，但不能让注视对象每帧变来变去。需要看向新对象时由真实业务输入决定目标，而非随机数决定剧情。

## 7. 律动与呼吸

### 7.1 轻轻晃着 `idle_sway`

整体是较慢、能停住的侧倾；不是每根轴都使用同频同幅正弦。

- 主周期约 3.0–4.2s，R 在约 ±2.5–3.5 内，Y 约 ±1.5，P 约 ±0.6。
- 一个周期可分为 0–30% 侧倾、30–45% 慢停、45–80% 反向、80–100% 回中心。两个方向轻重稍有不同。
- Y 比 R 的主要转向晚约 100–180ms；眼睛仍看向有效 attention，避免把摆动带成乱瞄。
- 前景手势在相应轴上出现时降低摆动；交还时继续流动的背景相位，而不是从中心重新启动一遍。
- 作为模型选用的背景内容；不增加“不倒翁工具”，不把真人呼吸叠成整模上下浮动。

当前自律只有 yaw/pitch 小幅正弦，MO 没有独立 torso.breath。拟议侧倾循环需要接入背景持续采样；不声称 source.background.idle 已经在 runtime 被消费。

### 7.2 找思路 `thinking`

整体：眼睛先离开观众，停在一个上侧方向，头轻歪后等待；想好时回看。避免左右不断摆动显得坐立不安。

- 进入约 0–350ms：G 到上侧约 (±0.3,+0.35)，头随后 R≈2.5、P≈1。
- 接下来约 350–1,200ms：留在关键姿势；语音嘴型不受这个背景控制。
- 思考继续：每约 2.5–4.5s 才一次小的重新定向或眨眼，其余保持很轻的动势；不每秒反复左右看。
- 结束约 350–500ms：先把目光交还有效 attention，头再收势；不替换长期姿态或神态。

背景提示是一个表演惯例，不证明 Uina 在此时有某种主观体验。当前 setThinking 只在 false→true 播放一次 1,200ms clip；持续状态存在不等于持续动作已经实现。需要同一个背景实例在状态存在期间采样，宿主启动/停止仍各一次；不靠重复宿主事件续播。

### 7.3 呼吸

保留 rig 的 `external.breath="vts"`。在本轮不增加呼吸通道，不修改模型物理，不叠加整模缩放。现有头部微晃已使用 7.3s/11.3s 不同周期；继续加“质数呼吸”既无新的可识别动作，也可能只形成机械叠波。

## 8. 完整演出如何由积木组成

下面是内容安排，不是当前可直接调用的 Performance API。姿态、表情、注视用现有工具；精细时间安排在作者内容/实际语音接缝完成，不让 LLM 靠两次工具调用的网络时差制造 80ms 相位。

### 听懂了，再确认

先 `attention=user`，在对方结束后的自然停顿做 `nod`；口头确认时保持轻笑。遇到不确定内容则 `curious`，不强行同时点头和摇头。主姿势分别是垂直应声和侧倾等待。

### 害羞但想回应 — 约 2.4s

0–450ms：`tuck` 进入、`avert_down` 生效。450–1,200ms：保持，不补脸红。1,200–2,000ms：`glance` 朝观众短看、再回垂眸。2,000ms 后：逐渐回 `rest/user`，或按剧情继续低头。轻笑可保持，但害羞不是一个专用表情工具。

### 有点得意，还想逗你 — 约 2.0s

`smirk` + `user`，随后 `chin_up`。昂头关键姿势结束后再做 `wink`，不把闭眼、抬头、甩头全挤在同一瞬间。前者的主记号是下巴与视线反差，后者是单侧闭眼。

### 惊到，然后重新确认 — 约 2.0s

先 `startle` 的快冲量；约 400ms 后短停，不立刻回摆。接 `curious` 或新增候选 double_take 的二次确认。普通信息惊讶使用 `surprise`，避免每句“哇”都猛烈后缩。

### 开心到弹一下

提前进入 `smile`；语句情绪落点触发 `joy_hop`，笑眼在上升顶点后出现，保持说话嘴型。动作归位后回到轻晃，不接一串重复整模弹动。

### 暗中看你

`edge_peek` 决定构图与临时注视；smile/smirk 可另选。短停时目光先看向观众，头晚一点跟；结束恢复原屏幕位姿。别与 face_closeup 同时占有 model:transform。

组合要尊重实际资源：头部的点头与摇头不能仅因为工具允许并发就任意求和；两个空间构图共享 model:transform，应明确冲突或顺序。不同职责的神态、头部姿态、注视可以自由组合；同一轴的竞争由引擎处理，不能把全世界工具统一串行化。

## 9. 当前实现能达到什么

等级说明：A=现有程序控制与有限动画语言足够，主要新增/重写目录内容；B=现有模型有对应手段，但需要程序适配、执行或接缝调整；排除项可能是效果证据不足，也可能需要改变本轮禁止修改的内容，不能一概宣称模型缺少资源。A/B 都不等于已通过真实画面验收。

| 项目 | 等级 | 实现判断与实际缺口 |
| --- | --- | --- |
| nod / shake / curious / chin_up / head_toss | A | 头、眼现有轴足够；关键帧、顺序、并行可表达。跨槽交还、头姿余量与 additive 冲突仍要按实际实现处理 |
| glance / eye_roll | A（单次动画）；B（严格目标交还） | 写现有 gaze 轨道能表现；“回到结束时最新 attention”需要目标交接，不能把静态最后一帧写死 |
| alert / surprise | A | 现有轴足够；幅度上限和说话口型限制决定最终效果。这里不承诺扩瞳或特殊圆嘴 |
| wink | B | 左右眼可独立闭合；最后的生理眨眼乘法会干扰，需按部位协调其窗口 |

## 10. 为实现这些效果值得做的程序调整

仅列这些内容真正需要的机制，不为“像动画引擎”增加新系统。

1. **关键姿势可到达、可交还。** 对作者提供入场/退出等实际有用途的播放配置；明确视线 Override 与 head compensation 的边界；从当前呈现状态进入，结束交还最新基底。同轴 additive 并发会累加裁剪，当前 `atomic` 也不是任意同级冲突都整场取消，不能以它代替编排。
2. **眼睑短动作协调。** Wink、惊吓、定格窗口里协调自律眨眼，结束恢复正常生理行为；只处理实际冲突部位。
   **接入已有面部自由度。** 在程序 rig 声明 Brows 的共同扇出、MouthX、CheekPuff；扩管道对这些模型专用轴的面部处理，不因 mo 前缀而绕过平滑。只用既有保存绑定，不拆眉、不改物理、不扩成全部 309 参数的通用工具。中性和幅度是待确认作者数据，不直接拿参数最大值当常态。
3. **空间和参数使用同一表演时间。** 扩展目录的可选空间内容为多段轨迹，依旧由统一播放入口执行。为弹跳和特写允许不同进入/退出时长；整模位置/缩放/旋转共用 model:transform。
4. **空间动作真正停止并归位。** 当前 playMotion 的等待监听 options.signal，未监听 claim.signal；safeStop 的 cancelClaims 因而可能取消不了空间推进。异常路径也没有保证恢复或终止骨骼 handle；这是当前源码问题，不是单纯动画设计不好。新内容前应连接 claim 中止、登记全部清理、在正确模型代次内归位，清理完成后再释放资源；失联时如实保留未知，不能误写新模型或声称归位成功。
5. **背景真正持续。** 同一实例持续采样轻晃/思考，前景遮挡时降低相关轴；不用无限长 clip 或反复工具调用假装持续行为。启动/停止仍走已有生命周期。
6. **反馈与证据匹配。** 当前 composeTick 注入没有带上播放贡献记录，而 fromEngineResult 会把按本地时间完成映射为 input_accepted。客户端已有观察接口不等于 runtime 已接好。先完成必要的贡献/确认接线，VTS 接受输入仍只证明输入接受；实际表现质量要看画面。

以上全部可在 World/authoring/director/adapter 及既有外部接缝范围完成；没有增加 Core 概念或改模型内容的必要。

## 11. 值得新增的候选与实施顺序

额外候选只推荐以下三个，不立即扩大首版目录：

| 候选 | 为什么有新轮廓 | 分解设计 | 可实现性 |
| --- | --- | --- | --- |
| 再看一眼 `double_take` | 第一次轻瞄，回正停顿后第二次明显转头；区别于 shake 的连续左右摆动 | 0–200ms 轻瞄、200–400ms 回正、400–650ms 头转约 7、650–1,000ms 停、1,000–1,350ms 收；眼先于头，嘴不强制参与 | 九轴足够；明确注视交还后可实现 |
| 笑到缩起来 `laugh_bob` | 两次不同轻重的前点加笑眼，中间留空；区别于 joy_hop 的整模上移 | 约 1.5s：P−4 的第一点、回弹并短留、P−2 的第二点、慢回；闭眼随主点，保留语音嘴型 | 不承诺肩膀耸动；需眼睑协调，现有模型可做头部版 |
| 松口气 `relax_sigh` | 先保持小紧张，再慢慢松开；有明显减速过程 | 约 1.6s：0–250ms 头略收，250–650ms 眼睑稍降，650–1,200ms P 慢回并轻侧倾，1,200–1,600ms 抬眼 | 可做可见姿态松弛；没有音频时不声称真实叹气，也不新增胸腔呼吸控制 |

实施价值顺序建议：

1. 先完成目录内容：nod/shake/curious/chin_up/head_toss/glance/surprise、基础姿态和明朗笑。随后接入既有歪嘴/眉毛/鼓嘴绑定，做偏嘴坏笑与气鼓鼓；这个扩展不改模型资源。
2. 再完成眼睑协调、急反应和背景持续：wink/startle/freeze/idle_sway/thinking；同一机制服务多种真实内容。
3. 修复空间取消/归位后，再做 joy_hop/face_closeup/edge_peek，最后做罕见 screen_spin。
4. double_take 可作为第一个新增内容；laugh_bob、relax_sigh 按实际区分度决定是否进入目录。

这不是工具隐藏或机械发布门。实现时先用最少的必要画面对照：同一 MO、同一构图、静音对比相似候选，再在说话状态观察关键姿势、交还和空间归位。自动化不能替代自然度判断。本轮不跑测试、不操纵真实 VTS，不把这些设计目标写成已实现能力。
