# Live2D 手工模型适配与动画复用设计

日期：2026-10-10。状态：部分实现。当前 MO rig v3 含 12 个控制；躯干输入准备与 `bodyMapping` 诊断可在源码中找到。作者草稿/发布流程、第二模型复用和真实视觉验收仍是设计目标，不能由存在 rig 配置推定已完成。范围：`.uina/worlds/live2d` 及具身端点接入；不新增 Core 概念。

采用 **手工模型控制配置 + 显式选择的逻辑动画 + 单一执行与输出链路**。每个模型拥有自己的可用动作目录；同一个 `nod` 可以复用公共动画、调整公共动画的参数，也可以选择完全专属的动画。运行时不根据参数名称自动选择表现，不把可写参数等同于好看的动作。

## 1. 当前事实和设计约束

本轮重新读取当前源码。已有工作树包含用户原有修改；本提案不改动它们，也不修改真实 VTS 模型和认证。

| 当前源码事实 | 对设计的约束 |
| --- | --- |
| `motion.ts` 已有声明式编排、编译和纯采样 | 保留这一套动画语言和播放器，不创建第二套运行时 |
| `model-adapter.ts` 找不到配置时仍调用 `suggestModelAdapter`；缺少 points 时使用数值端点生成校准 | 自动发现只生成作者草稿；正式运行必须加载显式模型配置 |
| MO 配置目前有参数 ID，但大多数条目没有手工校准点 | “写了 JSON”不代表已经完成视觉适配 |
| `MotionDirector` 合成后，所有目标仍经过 `BodyDirector` 滤波 | 创作时间线与实际输出之间存在额外响应延迟，必须显式决定是否保留 |
| `encode` 会给全部已绑定轴编码中性值或帧值 | 中性回落只能覆盖模型明确交给 Uina 的控制，不得重置 VTS 管理的部位 |
| 当前资源主要按 head/torso/gaze/eyes/mouth 通道申请 | 通道只能作为创作分类，实际冲突必须由输入和输出资源判断 |
| 当前 safeStop 只取消 director；翻转 finally 仍可能在租约释放后恢复位置 | 取消通知与清理完成必须分开；清理结束前保留写权限 |
| 翻转用 profile 对象相等判断同一模型 | 事实快照变化不能等同于模型切换，需明确的执行代次 |

历史 MO 磁盘检查曾记录头部/躯干跟随、嘴形关联和重复输出绑定；原附件 `MO-MODEL-COMPARISON.md` 当前不在 checkout 中，不能从该旧结论推断现行 VTS 内存状态或画面。本设计要求现场再次核验后才能发布模型配置。

当前适配和目录实现见 [rig adapter](../../../.uina/worlds/live2d/adapter/rig.ts)、[MO catalog](../../../.uina/worlds/live2d/models/mo/catalog.ts) 与[运行合同](../../live2d/live2d-world-runtime.md)。本提案不把历史问题一律当作当前仍未修复，也不把旧测试结果当作本提案的验证。

## 2. 作者维护的最小内容结构

建议在 Live2D World 内组织为以下结构；路径和 API 都是拟议结构：

```text
motion.ts                         保留：动画语言、编译、采样
motions/                          公共逻辑动画、可复用片段和动画工厂
models/mo/
  rig.json                        手工控制映射、曲线、跟随关系、来源约定
  motions.ts                      模型选择的公共动画和专属动画
  index.ts                        对外动作、姿态、待机、反射、嘴型、外观目录
  acceptance.md                   校准与实际画面验收记录
```

作者的日常工作流应当很短：读取真实模型事实 → 写一个主动控制的手工曲线 → 预览该控制 → 选择/调整一个动画 → 在实际背景与说话状态下预览 → 保存到模型目录。先提供轻量的诊断与预览入口，不为适配先建设大型编辑器。预览要能重复播放、立即停止、显示逻辑值/输入值/饱和与请求间隔；单轴预览只走作者指定的区间，不自动扫到模型极限。

手工草稿经过技术校验后可在显式作者预览中执行，但不自动进入 Agent 的日常目录；视觉尚未验收不妨碍创作。作者确认某个具体版本后将其发布到模型目录，相关内容变更后重新预览。草稿预览与发布动作共享同一执行链，仅目录可见性不同，不使用直接写参数的第二套播放器。

只有三类内容职责：

| 内容 | 回答的问题 | 应当修改它的情况 |
| --- | --- | --- |
| 模型控制配置 rig | 一个逻辑控制在这个模型上如何运动；谁负责写它 | 方向反了、中性不对、舒适幅度不对、绑定/来源改变 |
| 动画 | 控制在什么时候运动，怎样组合，怎样收势 | 点头太快、停顿太短、轻重顺序不对、需要另一套表演 |
| 模型目录 | 这个模型实际提供哪些表现，各种背景行为用什么内容 | 换角色气质、选择专属动作、调整说话/待机行为 |

目录是普通 TypeScript 组合，rig 是可验证的数据。无需补丁语言、无限继承、注册总线或通用约束求解器。运行时编译为不可变计划，播放时只采样、合成、编码。

## 3. 模型控制配置：一个输入只有一个主动控制

公共动画继续使用有明确语义的逻辑控制，例如 `head.pitch`、`mouth.form`。角度数值是创作单位，不能声称已经量到模型在画面中的真实角度。现有逻辑单位可以保留，避免为追求形式统一整体改成 0..1。

每个主动控制必须显式描述：

- 逻辑 ID、逻辑中性值、允许的创作区间。
- 唯一参考输出参数及 VTS 输入；两者都需核对实际绑定。
- 逻辑值到参考输出值的手工曲线，包含中性点；输出范围必须可达。
- 同一输入的其它输出、必要的物理跟随，以及与这些输出相关的来源约定。
- 此控制由 Uina 持续拥有，还是部位完全由 VTS 内置来源/物理管理。
- 实际使用的 VTS 平滑设置；它是适配契约的一部分。

输出中性点可以不同于模型默认值，但必须经过手工确认；正常睁眼也不能机械地取参数最大值。舒适区间可以不对称，不必覆盖模型极限。曲线要单调，方向在曲线中表达，避免 direction 与曲线同时决定方向。

运行时只用参考输出反算一次输入，随后检查真实 fanout 与声明一致。跟随输出不能再提供另一条独立曲线来争用相同输入。例如：

```text
head.pitch → 一个 VTS 输入 → ParamAngleY
                           → 保存绑定中的其它输出
ParamAngleY → 模型物理 → 身体/头发等跟随

mouth.form → 一个 VTS 输入 → ParamMouthForm
                          → 声明并验收过的其它输出
ParamMouthForm → 模型物理 → 笑眼等跟随
```

作者确认跟随效果合适，就保留它；作者需要独立身体或独立笑眼时，再专门准备独立输入，并处理对应输出的其它写入来源。不会为了把所有轴标成可用而删除模型物理。

同一逻辑控制确实要驱动多个独立参数时，可以配置多个目标，但每个目标使用自己的输入和曲线。两个主动控制共用输入，或两个主动控制写同一输出，配置编译失败。即使偶尔给出的数值相同，也不把它们授予独立能力。

MO 的成对眉毛如果需要创作，应当成为一个控制，例如模型内的 `mo.brows.raise`，以一侧作为参考、另一侧作为声明的跟随。不能把它冒充独立的 `brows.left` 和 `brows.right`。模型内控制的中性/范围/资源由该模型声明，沿同一动画编译与采样路径执行；只有遇到真实跨模型复用需求，才将语义提升为公共控制。不会为 MO 的全部自定义参数预先创建通用轴。

正式运行没有自动映射兜底。未适配模型可以读取事实并生成草稿，状态明确为“未适配”；模型变形动作不发布。整模型位移等独立能力单独核验、单独发布。

## 4. 动画复用：只保留三种选择方式

每个模型显式选择：直接导入公共动画、调用公共动画工厂，或使用专属动画。下面只示意内容组织，不是当前已有 API，也不提供已经校准的 MO 数值：

```ts
export const actions = {
  nod: {
    description: "轻点头一次",
    clip: nod({ depth: measuredNodDepth, durationMs: reviewedNodDuration }),
  },
  smile: {
    description: "轻微微笑，笑眼随模型物理自然变化",
    clip: moSmile,
  },
  greeting: {
    description: "这个角色的打招呼表演",
    clip: moGreeting,
  },
};
```

工厂只暴露作者确实需要的幅度、次数、时长等参数；节奏结构需要明显变化时直接写专属动画。不会让 adapter 根据当前模型偷偷缩短片段、删除主动作、挑选其它表现。

“改配置让模型适配同一个动画”适用于方向、中性、响应曲线和舒适幅度。例如同样的逻辑点头值在两款模型上需要不同参数值，修改各自曲线即可。若只有点头太深，而其它抬头动作正常，调整该模型选用的 nod 深度，避免改全局曲线损坏其它动作。若点头前后的停顿不对，改动画。缺少独立身体控制时，配置不能补出这一自由度，应选择不要求它的动画版本。

动作只写自己需要的控制。单纯点头不默认带上微笑、腮红、睁眼、躯干和视线；打招呼需要这些时在 greeting 中组合。底层持续维护已拥有控制的基准，所以省略一条动作轨道不等于把旧值永远留住。

可选装饰在模型目录编译时决定保留或去掉，形成一个具体版本，并参与视觉验收。运行时事实变了，就重新校验、撤下受影响动作；不会在一次已发布的点头里临时删掉半套表情却继续声称相同效果。

动作记录包含动作定义、描述、原子/局部抢占策略、说话协作和适用姿态条件。完整表演默认整场抢占；确实适合独立部位并行的动作由作者声明。原子只表示整场资源准入与取消，不表示画面回滚。

## 5. 唯一的执行链路与资源规则

```text
cue / express / preview / pose / 主体事件 / 音频电平
                           ↓
                Live2DRuntime：统一就绪与暂停检查
                           ↓
             当前模型目录：解析名称，选择具体动画
                           ↓
          校验实际基准、来源、模型代次和所需资源
                           ↓
             MotionDirector：采样、仲裁、交接、合成
                           ↓
               ModelAdapter：手工曲线与唯一输入编码
                           ↓
                   VTSClient：发送与请求证据
                           ↓
                    VTS 模型与保留的物理
```

保留现有模块，但职责按这条链路收敛。底层 play 不再成为产品入口的旁路；预览也走 Runtime，使用与正常运行相同的校验、资源、VTS 设置和输出。

资源至少包含主动输入和会被竞争写入的模型输出。按保存绑定与物理依赖计算影响关系，再与作者声明核对。跟随身体不必为一次点头申请全身独占；微笑写眼笑参数也不意味着必须禁止写不同输出的普通眨眼。`head/eyes/mouth` 等名称保留为描述和界面分组，不能作为“共享一个部位，所以全部互斥”的依据。

Uina 内部的同一控制由合成器决定唯一结果；层合成完成后才编码，一帧里每个 VTS 输入最多出现一次。不同输入若会竞争同一输出，在申请资源时协调。物理拥有且未交给 Uina 的输出不直接注入。

租约、合成贡献和请求确认归属于同一播放。不能靠全局接受计数判断某个动作完成。写入前检查取消信号和执行代次；取消后不再发送新的动作效果，已经发生的效果不假装撤销。

偏移动画在申请资源的同一个执行步骤里绑定实际基准。验证“基准 + 动画 + 被允许的背景贡献”的可达范围，而不是只验证中性，也不是把所有非零偏移都当作会覆盖全轴范围。姿态切换期间的动作可达性随实际绑定基准校验。

姿态改变可以在前台动作遮挡下推进底层基准；本次偏移动画保持启动时绑定的基准，退出融入新的底层。底层与前台以及交接期间的组合范围均需验证。无法证明可达时拒绝该组合，给出“当前姿态不适用”等原因；不静默截断作者的关键动作。

配置编译检查全部映射，而不只检查本次动作用到的部分；错误配置在控制前失败。运行中异常编码导致当前计划失效并停止相关动作，报告错误，不靠不断打印 tick 警告维持一个实际停止注入的“可控制”状态。

## 6. 动作节奏、待机与语音

关键帧插值负责已经创作好的运动时间线。交接过渡负责入场、抢占和回落。**已创作动画的最终合成值不再统一经过 BodyDirector 低通滤波。** 现有动态滤波如确有价值，仅用于音频包络或未经编排的连续目标，放在其来源进入合成前；不再二次改变全部动作。

VTS 输入平滑设为作者明确选择的固定值，原则上从最低必要平滑开始校准。若设备需要非零平滑，预览与实际运行采用同一设置，并纳入验收版本。不会用缩短动画、提高强度或多个响应滤波相互抵消来补偿不可见的延迟。

时间线采用渲染单调时钟。普通动画在卡帧后按真实经过时间推进，不突发补发历史帧。发送层只保留最新尚未发送的合成状态，不积压过期微表情。若错过关键表演阶段，记录此次动作呈现证据不足；不因为时间线到了终点就报告完整表演成功。显式整模型移动由其独立命令生命周期调度，不能与参数帧共用这一丢弃规则。

每个模型显式选择以下背景内容，未选择就不生成该行为：

- 中性基准和可用持续姿态。
- 待机轨迹、眨眼来源、呼吸来源。
- 思考、注意和重音等主体事件反应。
- 音频电平到嘴开合的手工响应曲线、开合包络与说话动作。

初始基准是作者验证的中性。不要全局强制“轻松”姿态、半闭眼、微笑、歪头、说话时晃动身体和视线补偿。待机应从静止基准逐项加入并验收，隐藏的装饰也属于动画内容。

呼吸、眼睑等部位逐一选择来源。VTS 内置眨眼负责时，Uina 不生成另一套眨眼或眼睑中性写入；需要作者眼睑表演时，在适配中明确交接来源，而不是临时强写。同一部位不能因为“背景”或“生理”之名绕过资源检查。

说话期间一般让 `mouth.open` 由电平驱动，`mouth.form` 由表情驱动。若模型在微笑时对张嘴的视觉响应改变，先验收组合；必要时作者显式写一个局部嘴型混合函数，且仍由单一合成器执行。模型未验证这项组合，就不把“微笑可以和说话并行”当作默认事实。保护张嘴编排的动作使用明确的 exclusive 策略。

## 7. 对 Agent 的界面

日常入口以命名动作和持续姿态为主：正文 `<cue id="nod"/>`，工具 `express({ motion: "nod" })`，姿态 `pose({ name: "attentive" })`。相同名称只承诺语义类别，具体视觉风格属于模型目录。

cue、express、姿态、status、端点 affordance 和预览都读同一份当前模型目录。Agent 看见的是已经发布且当前可用的动作及简短描述，不是全局动作全集加一长串底层失败原因。

工具使用稳定的结构和字符串动作 ID；动作名称在当前目录中验证。无需假设 World framework 能在换模型时热重注册 schema。模型切换后，目录投影更新；旧调用明确返回动作不可用和当前可用项，不能偷偷调用语义相近动作。

保留已适配片段的组合能力，例如作者发布的 head/gaze/face 片段或 beats；每个片段也必须来自模型目录，经同一编译与范围校验。日常默认不要求 Agent 写任意参数值，诊断/创作工具与日常表达分开。

拒绝原因应区分：未适配、尚未就绪、暂停、动作不在目录、当前姿态不适用、资源冲突、活动外部来源冲突。cue 的收到、开始和未播放原因应可查询；路由成功只能证明递交，不等于动作执行。

## 8. 停止、模型切换和外部来源

暂停状态由 Live2DRuntime 持有，所有入口与持续生产者检查同一状态。BodyRouter 只调用端点，不保存一份能够被 World 工具绕过的权威暂停状态。

safeStop 的顺序是：

1. 关闭新动作入口，暂停待机、反射、姿态过渡与嘴型驱动；增加动作取消代次。
2. 取消正在执行的动作与待发送贡献；允许已发请求结算，但不再产生新表演。
3. 保留还需清理的资源。翻转在同一模型代次上归位、回读，完成或明确失败后才释放 transform 资源。
4. 对仍由 Uina 拥有的连续控制保持最终选定的输入值。停止完成后再允许 resume 或新动作。

safeStop 不承诺全部画面静止：VTS 的头发/衣物物理或外部来源仍可能运动。结果应说“Uina 驱动已暂停，归位结果……”，清理失败或设备断线时如实 unknown。恢复从当前状态进入背景，不补演暂停期间的旧 cue 或旧音频电平。完全交还 VTS 控制是另一项 detach 行为，不能把停止发送当作冻结。

使用分工明确的代次：连接代次用于请求归属；模型加载代次用于辨别当前实例；控制配置版本用于使适配计划失效。普通状态快照刷新不会改变模型加载代次。模型卸载、加载、设备断线使旧播放失效，旧 ACK 不确认新动作，旧清理不写入新模型。

配置变化按控制相关性判断。涉及已拥有输入的绑定、范围、平滑、物理来源或模型资产时失效；位置、热键描述等无关变化不能被说成模型本体替换。版本更新仍要重新生成相应目录和元数据。

重连后主动读取当前模型与事实，不能只等待可能在断线期间错过的 ModelLoadedEvent。CurrentModel 的 `timeSinceModelLoaded` 可辅助恢复加载时间，VTS discovery 的 `instanceID` 可区分应用实例；结合请求时间界限、已知配置稳定区间，判断加载是否发生在配置准备之后。只有时间关系无歧义才作为新加载证据，不能把 ID 相同或 profile 对象更新当作证据。

VTS API 若不能提供加载中绑定与磁盘配置一致的直接证据，**同一个 modelID 的重新连接不能证明配置已加载**。证据不足时保持鉴权与事件订阅，提供显式“重新加载当前模型并验证”的操作：通过受控卸载/加载跨越明确的加载边界，遵守 API 冷却，观察响应与模型状态并重读事实；操作期间磁盘配置发生变化则此次验证作废。无法确认一致就保留未就绪并给出恢复操作，不能无限等待一个已丢失的旧事件。

外部表情和模型动画按资源审计。静态存在一个 motion 文件不表示它始终活动；能观察到活动来源时只影响重叠资源。无法确认其活动生命周期的热键不发布为安全的日常动作，不通过 API ACK 推断已经结束。手工包登记外观操作及是否可查最终状态；持久表情会保持来源占用，不能 ACK 后立即当作释放。已经交给 VTS 的热键可能排队，取消本地任务不能保证撤销它；停止结果必须包括尚未确认的外部效果，不能宣称已全部静止。未知外部 UI 改动仍是观察延迟的边界，需要在 status 中如实暴露。

## 9. 状态与验收

状态分别回答：设备连接是否就绪、当前模型是否有匹配配置、有哪些已发布动作、哪些因当前条件暂不可用、最近动作发生了什么。普通状态展示可用项和当前故障；底层绑定/来源详情在诊断中展开。

模型配置有效、作者确认画面、当前可执行是不同事实。画面验收记录绑定模型资产/控制配置摘要、动画内容摘要、背景行为、VTS 平滑与测试场景；改了相关内容，该记录不能继续证明新版本已验收。作者记录证明一次观察，不是对所有时序组合的永久保证。

执行沿用项目的 succeeded / failed / cancelled / unknown / not_started 语义。结果细节区分本地意图、时间线结束、实际贡献输入的 VTS 接受、可查询外部状态确认；API 接受不升级为“画面自然”或“整条轨迹送达”。

记录实际发送/接受间隔、贡献输入、丢弃/过滤、阶段采样缺口和饱和。对于短动作，可在动画中声明关键阶段窗口，用来发现点头下压或眨眼闭合阶段完全未送达；这些标记只用于判定缺失，不重新拥有一条播放时间线。不能确认关键阶段的动作给出呈现 unknown，并解释原因。无需逐帧持久化全部诊断数据。

| 必须验证的场景 | 合格标准 |
| --- | --- |
| 静止中性、单轴扫动、输入交还 | 方向/中性/舒适区正确；未拥有部位没有被重置；回退行为可解释 |
| MO 点头及笑容 | 身体和笑眼跟随符合作者选择，不被错误声明成独立轴 |
| 两套动画共享控制、独立动画并行 | 同输入只有一个合成值；输出争用在播放前协调 |
| 点头只在某个姿态越界 | 拒绝该组合或选择作者明确指定的版本；不拒绝所有正常姿态 |
| 微笑 + 说话、说话 + 保护嘴部动作 | 张嘴幅度、嘴形、笑眼实际画面经过验收，保护策略无旁路 |
| 中途切姿态、抢占和连续重触发 | 从当前状态连续交接；退出回到当下背景，没有旧片段补演 |
| 翻转途中停止，立即请求新动作 | 清理保留所有权；停止完成前新动作不写；归位证据明确 |
| 已取消的 costume 尚未触发 | 不发送热键；不报告成功 |
| 暂停后通过 cue、World express、音频及 Host 事件触发 | 全部遵守 Runtime 的暂停状态 |
| profile 普通刷新、模型切换、断线期间重载 | 刷新不假换模型；切换不串写；错过事件有明确恢复路径 |
| 慢确认、卡帧及关键阶段缺失 | 不突发补演；缺失不冒充完整呈现；返回可解释结果 |
| 第二款真实模型复用 nod | 公共动画经该模型映射/明确参数调整后可用，风格不合适则写专属版本 |

技术正确性使用生产编译器/合成器的确定性测试和协议模拟覆盖；自然度、实际跟随、语音同步、VTS 来源协作使用真实模型预览。预览允许静止背景以定位问题，验收必须再打开完整实际运行行为。

## 10. 实施顺序与删除项

1. **先收拢生命周期。** Runtime 统一暂停/取消，修复资源清理与模型代次；确保 costume 取消后不触发、flip 清理不越权。补对应生命周期测试。动画好看不能代替这些正确性。
2. **制作一个完整 MO 包。** 现场 capture，确认实际来源与重复嘴开合绑定；只修明确阻塞的接线。保留有价值的头身/笑眼跟随。先验收中性、嘴型、点头、微笑和组合，再加入待机与反射。这里的首批动作是验收起点，不是永久容量限制。
3. **按真实控制资源改造现有 director/adapter。** 从 MO 已确认的输入与输出关系建立唯一写入和仲裁；切开 authored timeline 与额外滤波；目录编译替代每次运行猜测。
4. **统一 Agent 目录与预览。** cue、express、姿态、status、affordance 同源，删除全局枚举造成的假能力和即时静默裁剪。
5. **用第二款真实模型验证复用。** 验证同一个 nod 的映射适配与工厂参数边界，决定哪些片段确实适合公共库，再补更多内容。

阶段 2 的预览先走现有生产链，以形成视觉基线；阶段 3 改变合成、滤波和资源规则后，必须重新验收，不能沿用阶段 2 的“看起来不错”。测试与内容迁移随每阶段进行，不先把 19 个动作全填满才看模型。

正式迁移完成后删除自动映射运行兜底、未选择的全局背景行为、全局动作能力全集、角色输出上的统一响应滤波，以及只记录本地暂停的重复权威状态。自动 facts capture、配置校验、可审查准备计划、备份/恢复继续保留。旧接口在迁移时明确替换或失败，不形成两套播放器和兼容控制链。

本设计完成的标准是：MO 的首批实际动作、语音组合和停止恢复通过同一生产路径验收；第二款模型证明至少一个逻辑动画能可靠复用。当前仅完成设计与源码核对，尚未证明这些真实画面结果。

官方协议核对依据：DenchiSoft/VTubeStudio README 中 InjectParameterData、HotkeyTrigger、CurrentModel 及 Events/README 中 ModelLoadedEvent。输入定期保持、VTS 输入平滑、同参数插件 set 冲突和模型事件语义属于外部协议约束；本提案不扩张为 API 已提供画面或磁盘/内存绑定一致性证明。
