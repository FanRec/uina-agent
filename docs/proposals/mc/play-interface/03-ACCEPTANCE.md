# Minecraft 游玩接口验收

以 [设计合同](01-DESIGN.md) 判断行为，以 [重构路线](02-REFACTOR.md) 判断所属切片。E1–E10 是施工及发布条件。每一项保留可复跑的场景、源码提交和实际断言结果。任务回执和模型叙述用于对照。游戏结果由服务器或独立观察确认，执行过程由调用与效果账本确认，交接由 Host 和实际模型请求确认。

## 切片通过条件

| 编号 | 对应设计 | 可观察的通过条件 |
|---|---|---|
| E1 · 逐步裁决 | P3 · S1 | 通过普通 `mc.call`、有身体资格的 `body.call` 和依赖子调用的 Native 能力走受控结果。成功保留原业务值。分别造成确定失败、取消、派发前拦截、派发后未知。核对结构化裁决、已确认部分、账本效果引用和实际派发。子调用效果未知时，依赖该结果的默认路径没有派发后续动作。另用显式捕获、重新观察和继续的 Program 证明可编排性保留。 |
| E2 · 一份结论 | P3、P4 · S1 | 同一任务版本的 `tasks.get` 与完成投递给出相同结论和已确认成果。分别验证部分成功后失败与部分已确认后未知。原回执保留，后续查证带新证据。重复投递和 Host 重启后，核对同一完成事件只进入一次可见输入历史。 |
| E3 · 一单固定顺序 | P2 · S2 | 第二步静态参数非法或使用仅根可运行的模式，返回步号且第一步在 Driver 无派发。完整序列以单句柄按序完成。用实际动作计数核对失败、取消或未知后尾部保持 `not_started`。受理后改写临时 Library 文件，旧任务执行已绑定材料，新任务解析新材料。执行端退出后对账，已派发未知和未派发可区分，写入无自动重放。 |
| E4 · 发现与自由组合 | P1 · S2 | 从正式工具入口看在线、离线与启用 Addon 的目录。常用示例使用真实 selector 和输入，精确视图能找到对应合同和原子能力。显式 selector 及 JS 能调用符合当前连接条件的低层与 Addon 能力。不同视图、运行入口和执行记录指向同一能力绑定。 |
| E5 · 受理后交还 | P4 · S2 | 用真实 Host、World 和受控 Provider 提交一单有可观测执行区间的后台任务。记录受理回执、前台轮次结束、仍在执行的任务和第二客户端点名或 Rhythm 的后续轮次。后续轮次可处理输入，原任务独立推进。一次任务完成消息在受理之后出现。Rhythm 按该 Profile 的有效时机触发。 |
| E6 · 常规备料 | P5 · S3 | 在真实 Paper 上分别从已备齐、库存仅差中间件、库存缺原料但附近可采三个起点，提交一次石镐与八支火把的目标。独立核对最低持有量。已备齐时无写入。库存路线缺原料时给出缺口，账本无采掘。允许附近采补时完成一条可重复的备料路径。 |
| E7 · 清格、站位与往返 | P5 · S3 | 在真实 Paper 上以目标正上方、可着地的目标脚位、阻塞的目标脚位测试到达。宽松邻近与精确站位各按其合同结算。用会连挖自身支撑的清格布场检查受阻格没有写入。至少一处有落差的通道由角色实际走通并返回，独立核对入口与终点脚位、必要净空和支撑。另用缺工具布场确认已挖部分保留、通行判为受阻、序列尾部无派发。 |
| E8 · 部分效果、决定与停止 | P4、P5 · S3 | 在真实 Paper 的确定装料边界制造一次中断。独立读取炉槽，回执中的炉址、已装数量和未知量与证据对应。用具名决定在同一任务下产生一个新段，只取货或补缺。再用显式序列续段验证只执行新提交的步骤，旧段尾部保持未派发。重复选择、过期决定和等待期停止均核对派发记录。对照普通序列退出和合资格根任务的重启恢复，后者还需核对存档、维度和旧写端退役。用旧格式任务与已有 JS 流程夹具验证读取、恢复资格及来源，读取旧历史时无派发。 |
| E9 · 保存、发现与复用 | P6 · S4 | 从真实完成的任务保存固定序列，核对名称、来源与证据，清掉测试会话上下文后由目录找到，在不同初始库存上执行同一流程。用一个有现场分支的手写 JS 流程验证可独立创作、保存和调用。修订流程后，原任务仍能复查冻结材料。只有编译证据的流程显示可运行，已验证标识能追溯到对应玩法证据和适用条件。用同一失败经验分别验证条件匹配时能找到、无关时不会跟随回执。 |
| E10 · 连续游玩 | P1–P6 · 发布 | 完成下述真实模型对照和发布门。 |

## 连续游玩场景

用开工基线与候选提交做成对对照。固定真实模型版本与思考设置、服务器版本、玩家给出的目标和同场景的初始世界、背包、记忆条件及权限。使用临时 Profile、会话、Library 和独立存档。每组重置现场，布场动作留在独立管理端，真实玩家的配置、存档和历史保持原样。常规游玩和自创流程各准备两种起点，保留每次实际结果，包括失败及中止。涉及 [游玩信息交付计划](../play-context-refactor-plan.md) 时，两侧使用同一上下文策略测接口，另用该计划的场景测信息交付，最后在两项都开启的生产路径上复跑。

| 场景 | 给模型的任务与干预 | 通过条件 |
|---|---|---|
| 日常开局、采矿、回入口 | 玩家要求备好石镐和八支火把，采四个粗铁并带回洞口。两种可解布场改变初始库存和矿道布局。任务处在后台执行时，由第二客户端点名提问。玩家用可理解的游戏目标表达，无工具名、代码或步骤提示。 | 两种候选布场都由服务端确认产出和返程。模型能把已经决定的多步行动一次交付，并在等结果时结束一轮。实测至少一次在任务仍执行时处理第二客户端输入。完成通知后接得上原目标。等待期间没有仅为重复索取同一任务状态的查询，必要的现场观察和查证单独记录。 |
| 受阻、续段、接管 | 复用 E8 的炉子中断。模型只能看到正式接口给出的回执和事实。随后由玩家给出接着取货或停止的要求。 | 模型利用已确认进度和现场复查处理余量。真实游戏副作用与所选动作一致，核对无重复装料。停止分支用独立布场验证停止后无新的任务写入。 |
| 创作一次，换地方继续用 | 给一个需要根据材料或地形选择做法的施工目标。完成后请模型把有效做法留给下一次。在另一场地的新会话提出同类目标。 | 第一次能用 Program 或合适的已有能力达成目标。第二次能从目录找到并复用合适材料，对现场差异作合理调整。两次以真实施工成果核对，使用已有技能与自创流程走同一入口。 |

每次保留主体轮次和请求时间线、Minecraft 前台调用与请求参数、Task/Call/Effect 引用、事件进入模型上下文的时间、游戏前后读数。指标按玩家目标分别统计，包括完成率、前台 Minecraft 调用数、重复等待查询、提交正文体量、模型请求数及 Provider 报告的输入与输出用量。缓存读取分列。记录每次查询的目的，区分查新事实、控制动作和重复等待。受控 Provider 只提供运行链路证据。

每种常规起点按交替顺序预先安排至少三组成对运行。候选的实际目标完成率须不低于基线，每种起点都要完成至少一次。比较双方都达到目标的成对运行，每种起点至少保留两对。候选前台 Minecraft 往返数的中位数在两种起点上均须下降，常规场景的模型请求数和 Provider 输入用量中位数均须不升，按 Provider 口径另报缓存读取。对比一条等价短序列和内联 JS 的提交正文，短序列须更短。统计从玩家提出目标到完成交接的整段请求，计入查找、等待后恢复和完成通知。Provider 未报告 token 时记未知，并用能报告用量的同一模型版本重跑两侧再判门槛。

未完成的运行进入完成率及故障记录。先用失败证据区分能力缺失、信息交接失败和模型选择。候选路径修复后重跑相同场景。基线始终达不到某个目标时，保留该项能力差异，另外预先指定双方都能完成的同类常规场景做成本对照。门槛未达到时，沿实际请求找出是发现、提交、执行还是交还造成额外往返，修复后复跑。

## 发布门

1. **代码与协议**。记录 `pnpm typecheck`、`pnpm test`、`pnpm build` 的结果。复用 `tests/mc` 中的 Runtime、投递、目录、Library 和 Native Facade 测试，以及 Host 的 Rhythm 测试。对 S1–S4 新增行为，补现有覆盖缺少的断言。已有基线失败须在基线实际复现并记录，对本次范围有影响的失败解决后再放行。
2. **真实世界与发布入口**。复用 `pnpm dev:mc:native --rhythm-flow` 验证受控链路，从 `pnpm dev:mc:model --autonomy` 接入真实模型，从 `pnpm dev:mc:climb`、`pnpm dev:mc:stations` 和 `pnpm dev:mc:production-repair` 复用真实布场和独立读数。现有脚本覆盖按实际断言记账。缺失场景补到对应 dev 入口。通过源码和构建入口各复跑受理、让出、完成投递和 Library 执行。切换在旧数据副本先演练，对账后才推进目标环境。
3. **闭环评审**。评审者用记录里的同一任务标识，从请求、调用、效果、服务端事实到 Host 投递至少独立核对一次常规闭环和一次异常接续。变更历史链接到每项 E1–E10 的提交、复跑命令、证据位置、结论和剩余验证边界。缺少真实服务端或真实模型对照时，该项保留待验收。真实直播互动未发生时，把结论限定在已复验的场景。

发布时以这三道门的实测记录为准，覆盖完成后按 [重构路线](02-REFACTOR.md#切换历史与权威文档) 回填权威合同并归档本提案。
