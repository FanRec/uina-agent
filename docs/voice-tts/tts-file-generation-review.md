# TTS 文件生成审查与修正

> 历史审查快照：原稿未记录准确执行日期或源码基线；下方缺陷复现、测试计数与门禁结果只对应当次工作树，不代表当前 checkout。当前审阅结果见 [逐篇审阅台账](../document-audit-register.md)。

范围仅为刚新增的 `tts_generate`、Bridge 文件合成路径、对应测试和合同。已有 B 站、Host 等工作树修改不属于本轮。

## 判断

保留现有分工：工具接收台词并返回普通文件；Bridge 复用模型与合成锁；QQ 自持上传 staging。这个边界确有独立生命周期和失败职责，不需要新的 Core 接口、资产服务、任务轮询或租约。

旧实现的“生成与播放分离”和“发布后不因取消改判失败”有测试支持，应保留。但测试通过不能替代对字节校验和失败语义的逐项核验；本轮复现了下面的缺陷。

| 问题 | 原行为与证据 | 本轮纠正 |
| --- | --- | --- |
| 文件标识校验失真 | ascii 解码清除字节高位。对 RIFF/WAVE/fmt/data 标识设置高位，扩展仍发布文件并返回 succeeded，四例复现失败 | 保留所有字节位，非法标识不能冒充合法 FourCC |
| Bridge 虚假成功 | Python wave 的头信息与整数帧计数不足以证明完整 PCM。零采样率、错误字节率、未对齐数据三例均返回 HTTP 200 | 明确校验 RIFF、每个 chunk 边界、PCM 编码、速率与块对齐；不完整音频返回 502 |
| 回执遗漏可行动原因 | 参考音频不存在和 Bridge 停止都只返回“HTTP 503，请检查 inspect”，具体原因只在模型看不到的 details | 仅按已知状态码和原因映射简短正文；未知响应与日志仍留在 details，不擅自推断 |
| 外部诊断混入正文 | 文件系统错误的原始路径和多行文本直接拼进模型回执，已用含多行内容的写入失败复现 | 发布层生成受控错误说明，原始诊断留在 details；传输中断也统一在客户端边界处理 |
| 必需端口被当作可选能力 | 缺失 registerTool 时扩展仍完成激活，实际工具未注册 | 使用真实必需端口与 pi.cwd；错误宿主在启动伴生服务前明确失败，不猜根目录 |
| 期限参数被隐式改写 | Bridge 接受字符串期限和布尔值；true 被当成 1ms，产生超时而非参数错误 | timeout_ms 只接受 1–2147483647 的整数，与扩展的实际定时器合同一致 |
| 取消覆盖已确认失败 | 文件发布已经返回明确错误，清理中到达取消后却被改报 cancelled，实际复现 | 按触发异常的原因结算；后到的取消不能掩盖已确认的发布失败 |

新增的严格期限校验只改变文件生成接口：字符串、布尔值和越界期限现在返回字段级 422。合法模型工具输入与既有播放接口保持原合同。

## 重构顺序与结果

1. 先写针对缺陷的复现，确认原实现确实失败，再修正。
2. 将 WAV 校验、独占临时写入、原子发布、清理和发布结论收拢到私有 publishWav。工具执行体只安排合成、期限/取消和结果呈现。文件发布成功是该操作内部的不可逆结论；后来的取消与清理失败不会伪造失败。
3. 统一 TypeScript 期限默认值与校验入口，消除配置和工具工厂的重复规则。测试复用独立构造的 PCM fixture，避免两份重复头生成代码。
4. 移除文件生成路径额外的 threading.Event。断连由端点取消异步任务，服务取消自己的 HTTP 工作并释放锁；关闭事实仍由服务的既有 closing 状态表达。保留总期限检查，不能只依赖 HTTPX 单次读取超时。
5. 更新合同并重跑相关与全量检查；不通过扩大接受格式、丢弃原因或改动无关代码来让检查变绿。

模块深度来自对完整操作的封装，而非新增文件数量。publishWav 和字节校验均为私有实现；对模型仍只有 tts_generate({text})，成功结果仍只有 resource 和 durationMs。错误类型用于区分可以呈现的受控说明与原始异常，不承载额外业务状态。

## 有意保留的限制

- 两端校验不合并：Bridge 要保证 HTTP 交付事实，扩展要保证最终文件事实，两者可以独立部署。校验规则应一致，但跨语言不能假装共用一个运行时函数。
- 旧播放路径的 _wav_metadata 不在本轮改写范围；不能将本轮完整文件校验的结论推广到所有历史播放接口。
- 取消 HTTP 不证明 GPU 推理已停止；有效 WAV 不证明发音完整、语义正确或对端已听见。
- 断连/期限能够取消网络等待与锁等待；本地文件 I/O 仍通过发布前检查收束，不能宣称任意文件系统操作均可在期限瞬间被强制停止。
- 中间件清理失败可观察于 details，成品不自动过期。崩溃后的孤立文件不猜测归属、不自动删除。
- 本轮自动化验证使用隔离合成替身与 localhost HTTP，未运行真实模型或向 QQ 写入。以上结论来自源码核验与实际复现，不代表真实模型验收。
