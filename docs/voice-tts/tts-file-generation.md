# TTS 文件生成

`tts_generate` 只将完整台词合成为本地 PCM WAV 文件。生成和播放是不同用途：生成结果可以交给 QQ 或其他接受普通文件资源的工具；不会建播放任务、发字幕、驱动口型或发送 QQ 消息。语音维护仍使用 `tts`，本地发声仍使用 `voice`。

## 模型合同

唯一输入：

```json
{"text":"我刚才在直播，现在看到你的消息了。"}
```

工具说明：`将 text 合成为 WAV 文件，不播放。返回 resource 可交给支持文件的工具。`

成功正文（路径和时长仅为示例）：

```json
{"resource":{"kind":"file","path":"E:/Uina/Uina/uina/tmp/tts-<uuid>.wav"},"durationMs":3200}
```

`resource` 可原样传给消费工具。`durationMs` 从收到的完整音频采样数和采样率计算。正文不重复台词，不包含任务编号、编码后的音频、播放回执、模型参数、HTTP 日志或通用操作提示。完整错误与临时文件清理诊断放在 `details`；它不进入模型上下文。失败正文提供简短原因，接口缺失时提示更新并重启 Bridge；不返回可用文件引用。

参数只接受非空文本，拒绝附带输出路径、播放或发送参数。文本原样交给 Vendor，不经过自动朗读的分句、Markdown、括号或 Emoji 清洗，不悄悄截断。实际发音质量、标点和 Emoji 的读法由部署的模型决定，不能仅从 WAV 格式校验证明。

## 文件与生命周期

- 以 `pi.cwd` 为项目根，成品和中间文件均在 **`<项目>/uina/tmp/`**，不是 `.uina/tmp/`。本轮不迁移历史产物、播放缓存或其他工具已有数据。
- 成品名为 `tts-<uuid>.wav`；中间件为同目录 `.<名称>.part`。模型无需安排文件名或维护临时目录。
- 收到完整响应后，校验 RIFF/WAVE 长度、PCM 格式、采样率、声道、块对齐和实际数据长度；拒绝空音频、截断音频、HTTP 200 JSON 或不支持的音频格式。
- 先独占创建中间件、写完并同步，再通过同目录硬链接原子发布；已有目标绝不覆盖。文件系统不支持此操作时明确失败，不降级为可能暴露半成品的写法。
- 本次调用清理自己创建的中间件，不删除其他文件。已发布成功的文件不因取消、回合结束、`voice.interrupt`、静音、扩展卸载或播放缓存清理而消失。
- 成品保留至用户或独立文件管理流程显式清理。暂不增加租约、句柄、引用计数、自动过期或新的清理工具；目录已被 Git 忽略。进程崩溃可能留下中间件，后续合成不扫描或删除未知文件。

## 执行与失败边界

两端按同一 PCM WAV 字节合同校验；已知参考音频、连接、停止和坏音频原因进入简短失败正文，未识别的外部诊断不直接拼入模型上下文。文件发布由单一内部操作维护已确认结论，断连通过异步任务取消处理。后续审查的复现证据与重构取舍见 [TTS 文件生成审查与修正](tts-file-generation-review.md)。

扩展注册独立工具；Bridge 的 `POST /v1/tts/generate` 接受 `{text, timeout_ms}`，等待合成完成后返回 `audio/wav`，不把 202 受理当成成功。它复用同一个 Vendor 进程、语音预设和合成锁，以及普通批量合成的 payload 构造。生成强制请求 WAV，使用现有语言选择规则，不改模型或参考音频配置。

部署可通过扩展配置 `generationTimeoutMs` 调整生成总期限，默认 120000ms，独立于用于短请求的 `requestTimeoutMs`；这个配置不增加模型参数。调用方和扩展生命周期的取消信号覆盖 HTTP 读取和本地发布前检查。Bridge 同时核验总期限、客户端断连和关闭状态；等待共享锁时也可取消。文件生成使用异步 HTTP 请求，取消或到期会关闭其响应并释放合成锁，持续涓流不会绕过总期限。

客户端断开 HTTP 不证明 Vendor GPU 推理立即停止；Vendor 没有可验证的推理取消接口。可保证的是停止等待、丢弃迟到数据、不发布文件和释放本地锁。静音或播放 epoch 不参与生成判定。发布完成就是已确认本地事实，此后到达取消仍返回 `succeeded`。超时和失败不会自动重试，也不返回 `unknown` 伪文件；进程中断后的工具历史恢复仍遵循 Runtime 既有结算合同。

旧 Bridge 没有新接口时，生成明确失败并提示更新重启；既有播放协议继续保持原合同，不自动杀死外部服务。Core、Host 和 QQ 不增加 TTS 专有概念。

`generationTimeoutMs` 必须是 1–2147483647 的整数毫秒，符合 Node 定时器范围；无效值在扩展装配时明确拒绝，避免超范围值被定时器悄悄缩为 1ms。

## 与 QQ 组合

生成成功后，在已有 QQ `speak` 调用的 `content` 中使用：

```json
{"type":"audio","resource":{"kind":"file","path":"<复制生成结果的绝对路径>"}}
```

账号、会话和发送权限仍由 QQ 调用决定。QQ 检查允许根目录，复制到自己的 staging 后上传，维护其 `unknown` 屏障和证据，不自动重发。项目默认允许根通常涵盖此产物；部署显式限制媒体根时仍可能拒绝，不能绕过限制。生成成功不证明 QQ 平台接受、对端播放或内容读法正确。

## 验证

本地测试覆盖完整文本、精简回执、独立扩展激活与卸载、可复用文件、唯一命名、截断及错误音频、发布前后取消、碰撞不覆盖、超时、锁等待、慢速 HTTP 总期限及断连，以及 legacy/v2 payload。测试依赖隔离的 HTTP 服务和合成替身，不启动真实 Vendor、声卡或向 QQ 发送。

```text
pnpm exec vitest run tests/tts-generate.test.ts tests/tts-companion-lifecycle.test.ts
python -m pytest .uina/extensions/tts/bridge --basetemp=uina/tmp/pytest-tts -q
```

真实 Vendor 合成质量与延迟、部署后的 Bridge 兼容性以及指定 QQ 对端听到的语音，需要另行现场验收。
